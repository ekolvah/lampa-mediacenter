## Context

Причина дублей — proposal.md, **Why**. Наблюдения (приставка, 2026-11-23):

1. Экспорт ядра (`http://lampa.mx/app.min.js`, `var Favorite = {…}`): `check: cloud`, `toggle: toggle$b`,
   `get: get$b`, `all: all$2`. Карточка, меню и экран «Избранное» зовут функции через объект:
   `Favorite.check(` — 9 мест, `Favorite.toggle(` — 4, `Favorite.get(` — 5; `window.Lampa` отдаёт тот
   же объект (`Favorite: Favorite`). Значит, замена `Lampa.Favorite.check/toggle` доходит до UI.
2. Внутри модуля вызовы идут замыканием: `toggle$b` берёт `cloud(card)`, а `all$2` — `get$b`. Замена
   `Lampa.Favorite.get` экран «Избранное» (`Favorite.all()`) не изменит.
3. При синхронизации `get$b` читает `Account.Bookmarks.get(params)` через объект. Проверка
   (`tools/cdp.py`): временная замена `Lampa.Account.Bookmarks.get` на `slice(0,1)` →
   `Lampa.Favorite.get({type:'book'}).length` = `1` (без замены — 10).
4. Покрытие `imdb_id` в закладках аккаунта: `book` — 9 из 10, `like` — 5 из 9; без него только KP-тайтлы
   российского производства («Жизнь заново», «ИИнга», «Красота»…), у которых и нет пары в TMDB.

## Goals / Non-Goals

**Goals:** одна карточка тайтла в списках закладок и согласованная кнопка закладок, без правки данных
аккаунта.

**Non-Goals:**
- Сведение записей без `imdb_id` (поиск по названию и году): асинхронен, а `check`/`toggle` ядра
  синхронны; пар у таких записей на аккаунте нет (наблюдение 4).
- Разовая чистка существующих дублей в аккаунте: запись в общий аккаунт CUB без действия пользователя.
- Схлопывание списков без CUB-синхронизации: устройство работает с синхронизацией (решение 6).

## Decisions

1. **Ключ — непустой `imdb_id`.** Он есть у карточек `tmdb`/`cub` (детали тайтла) и у `kp_source`.
   Альтернатива — TMDB id из `resolveTitle`: его знает только память открытых в этом сеансе
   KP-карточек, а схлопывание при чтении идёт по сохранённым записям, где есть лишь `imdb_id`.
   Повторная закладка дубля не создаёт: `toggle` подменяет карточку на сохранённую (решение 3).
2. **Схлопывание при чтении — обёртка `Lampa.Account.Bookmarks.get`.** Она одна покрывает `Favorite.get`
   и `Favorite.all` (наблюдения 2, 3). Один проход с объектом `seen` (история — сотня записей и читается
   часто): группа записей одного `imdb_id` показывается одной записью на месте первой; это запись
   `tmdb`/`cub`, если она в группе есть, иначе первая. Причина выбора: часть читателей ядра берёт только
   `tmdb`/`cub` — расписание серий (`Timetable`, `favorites()`), скан истории рекомендациями,
   `Favorite.continues` («Продолжить»), карта «просмотрено» `recsGet` плагина; KP-запись на месте пары
   скрыла бы от них тайтл. Альтернатива — удалять дубль из аккаунта: необратимо и без согласия
   пользователя.
3. **`check` и `toggle` ищут пару по каждому типу.** Карточка без `imdb_id` сразу уходит в функцию
   ядра — ряды каталога (у карточек списков TMDB `imdb_id` обычно нет) не платят ничего.
   - `check(card)`: ответ ядра дополняется по каждому типу отдельно — тип, где своей записи нет, но есть
     запись того же `imdb_id` (исходный, не обёрнутый `Account.Bookmarks.get`), получает `true`, и `any`
     тоже. Не «только если меток нет вовсе»: ядро кладёт карточку в `history` при каждом запуске
     (`Favorite.add('history', movie, 100)`), и проигранная KP-карточка иначе не увидела бы закладку из
     TMDB.
   - `toggle(where, card)`: записи списка `where` того же `imdb_id`, включая свою, собираются до вызова
     ядра. Нет — `toggle` ядра с карточкой (добавление). Есть — `toggle` ядра с первой из них (ядро
     снимает её и соблюдает взаимоисключающие `marks`), затем `Lampa.Favorite.remove(where, r)` для
     остальных, без уже снятой: при синхронизации снятие асинхронно (`remove$3` шлёт событие, список
     обновляется через 500 мс), и исходный `get` ещё отдаёт снятую запись. Возврат — как у ядра,
     `return find[where] ? false : true`.
   - Взаимоисключающие метки (`marks`): ядро снимает прежнюю метку только у переданной карточки
     (`var added = marks.find(a => find[a]); if (added && added !== where) remove$3(added, card)`, `find =
     cloud(card)` — по её id). Поэтому если `where` — метка, записи того же `imdb_id` в `where` нет, а
     другую метку держит запись того же `imdb_id`, `toggle` ядра зовётся с этой записью: ядро снимет
     прежнюю метку с неё и поставит `where` ей же, метки не разъедутся по источникам.
   Индекс `imdb_id → запись` с инвалидацией не вводится. `check` ядро зовёт для каждой отрисованной
   карточки, и у сохранённых записей рядов «Избранное», истории и «Продолжить» `imdb_id` есть. Замер
   (приставка, 2026-11-23, `tools/cdp.py`): `Favorite.check` плюс поиск того же `imdb_id` исходным
   `Account.Bookmarks.get` по всем 9 типам для каждой из 90 записей `Favorite.all()` с `imdb_id` —
   `{"cards": 90, "types": 9, "total_ms": 58, "per_card_ms": 0.647}`, худший случай, ниже кадра.
4. **Место — `plugins/kp-reactions-fix.js`, раздел «Закладки».** Плагин уже подключён и сводит KP с TMDB;
   новый файл потребовал бы ещё одного URL в списке плагинов и отдельной выкатки. Обёртки — идиомой
   плагина: `var orgX = obj.f` и маркер повторного патча, как `KP.__reactions_patched`.
5. **Видимость сбоя (§IV).** Нет `Lampa.Favorite.check|toggle|remove` или
   `Lampa.Account.Bookmarks.get` — `Lampa.Noty` и `console.error` с именем, обёрток нет: по образцу
   `recsMissing`/`recsFailed`, проверка путей которого обобщается на путь любой глубины
   (`Account.Bookmarks.get` — три звена).
6. **Без синхронизации — ядро как есть.** Без неё ядро читает локальное хранилище, а обёртки ищут в
   хранилище CUB. `Lampa.Account.Permit.sync` — живой геттер, поэтому решение принимается при каждом
   вызове: ложно — все три обёртки отдают вызов ядру без изменений, `console.warn` один раз за сеанс.

## Risks / Trade-offs

- Проход плагина по KP-истории (`historyRecs`) не увидит KP-запись, у которой есть `tmdb`-пара: её
  сканирует ядро, а `recsGet` видит `tmdb`-запись (решение 2). Ловит тест
  `recs with tmdb and kp pair in history` (пара с одним `imdb_id` в фикстуре).
- Ядро поменяет имена/порядок вызовов → живая проверка `tests/live/favorites.sh` краснеет.
