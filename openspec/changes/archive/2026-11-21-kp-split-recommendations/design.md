## Context

Мотивация и наблюдение на приставке — в proposal.md. Код ядра, на который опирается решение,
прочитан в двух местах: исходник `yumata/lampa-source` `src/core/recomend.js` и `src/components/recomend.js`
(`gh api repos/yumata/lampa-source/contents/...`, 2026-11-21) и бандл, который грузит приставка
(`curl http://lampa.mx/app.min.js`, 2026-11-21).

- `search()`: `let recomend = Storage.cache('recomends_list', 100, [])`, затем `recomend.push(e)` для
  тайтлов, которых нет в списке и в истории (`h.id == e.id`) и чей год больше текущего минус 20, затем
  `Storage.set('recomends_list', recomend)`. Тип при этом не учитывается: фильмы и сериалы в одном
  массиве.
- `Storage.cache` (на приставке, `String(Lampa.Storage.cache)`): `else if (result.length > max) {
  result = result.slice(result.length - max); set(name, result); }` — остаются последние 100.
- `get(type)` ядра: фильтр типа по `number_of_seasons || first_air_date`, `.reverse()`, затем
  `!history.find(h => h.id == e.id)`. `page(object, call, empty)`: `get(object.media)`, срез
  `(page - 1) * 20 … page * 20`, пустой срез — `empty({status: 404})`, иначе `call({results, title:
  Lang.translate('title_recomend_watch'), total_pages: Math.ceil(all.length / 20), page})`.
- **Экран «Ещё» зовёт `page` через свойство объекта, а не внутреннюю функцию.** Бандл
  `app.min.js`: строка 54571 `var Recomends = { init: init$w, get: get$4, page: page };`, строки 54586
  и 54589 `Recomends.page(object, this.build.bind(this), this.empty.bind(this));` и
  `Recomends.page(object, resolve.bind(this), reject.bind(this));`, строка 67577 `Recomends: Recomends,`
  в объекте `window.Lampa`. Значит, замена `Lampa.Recomends.page` меняет экран «Ещё». Ряд ядра
  `recomend_watch` (Главная `tmdb`/`cub`) зовёт внутренний `get$4` и замену не видит.
- Плагин уже подписан на `Lampa.Storage.listener` `change` по `recomends_list`
  (`followRecs`, `plugins/kp-reactions-fix.js:697`), но подписывается только после прохода по
  KP-истории и только если KP-тайтлы найдены. Наблюдение о том, что запись ядра видна этому слушателю
  с полным массивом в `e.value`, — в архиве `2026-11-20-kp-history-recommendations/design.md`
  («Запись ядра видна через `Lampa.Storage.listener`»).
- Ряды Главной KP (`recsRow`) уже берут тайтлы из `Lampa.Recomends.get(media)`, «Ещё» — через
  `Lampa.Router.call('recomend', {media, total_pages})`.

## Standard approach

none found: штатного способа разделить рекомендации по типу нет. Ядро
(https://github.com/yumata/lampa-source/blob/main/src/core/recomend.js) держит один список без
разбивки по типу и без настройки размера (код выше). Готовые плагины: поиск по `recomends_list`, `Lampa.Recomends` (GitHub
code search, веб-поиск) описан в issue #77; результат тот же — `nb557/kp_source.js` только читает
`Lampa.Recomends.get()`, `smart_recommend.js` (BazZziliuS) строит отдельный пункт меню по KP id. Подхода
«разные списки по типу поверх списка ядра» не нашлось. Поэтому правка в своём плагине, где ряды уже
строятся.

## Goals / Non-Goals

**Goals:**
- Рекомендации сериалов не вытесняют рекомендации фильмов и наоборот.
- Ряды Главной KP и экран «Ещё» показывают один и тот же список своего типа.

**Non-Goals:**
- Фильтры по жанру, рейтингу, числу голосов — решение пользователя: фильтр только по просмотренному.
- Своё сканирование TMDB и ранжирование «по голосам» нескольких фильмов истории.
- Изменение сканирования ядра: очередь, период 120 с и правило года (последние 20 лет) остаются
  ядру.
- Ряд ядра `recomend_watch` на Главной `tmdb`/`cub`: он берёт внутренний `get$4`.

## Decisions

### 1. Списки типа пополняются из записей ядра

Два ключа Storage: `kp_recs_movie` и `kp_recs_tv`, массивы тайтлов в том виде, в каком их пишет ядро.
На каждый `change` с `e.name === 'recomends_list'` функция `mergeRecs(lists, coreList)` для каждого
тайтла `coreList` по порядку убирает его из списка его типа (по `id`) и добавляет в конец. Потом у
каждого списка, длиннее 500 (решение 4), срезаются первые. Список пишется `Lampa.Storage.set`, только если
порядок его id изменился: ядро на тике пишет `recomends_list` дважды (обрезка в `Storage.cache` и
`Storage.set` в `search()`), и вторая запись ничего не меняет. Так
хвост списка типа повторяет тайтлы этого типа из записи ядра в его порядке, а перед ними остаются
старые тайтлы, которые ядро уже обрезало.

Сохранённый ключ читается с проверкой формы, как `readSeen` (`plugins/kp-reactions-fix.js:483`):
не массив объектов с `id` — `console.warn('kp-reactions-fix: recommendations: bad <ключ>')` и пустой
список. Иначе исключение вылетело бы в слушателе `change` внутри записи ядра в `search()`.

Подписка ставится при установке патча, независимо от прохода по KP-истории. При установке
`mergeRecs` вызывается и над текущим `recomends_list`: так подхватываются записи ядра, сделанные без
плагина, а при первом запуске списки заполняются (на приставке сразу будет 15 фильмов и 100
сериалов, дальше список фильмов растёт по мере сканов фильмов ядром). Повторный вызов над тем же
списком ядра ничего не меняет: тайтлы уже стоят в конце в его порядке.

Отвергнуто:
- «Свой скан TMDB по истории каждого типа». Дублирует сканирование ядра, добавляет запросы и код
  очереди. Ядро уже сканирует всё, что нужно; теряется только из-за общего лимита.
- «Поднять лимит ядра». Лимит 100 зашит в `search()`, снаружи не меняется.
- «Брать только новые тайтлы записи (дельта к прошлой записи)». Нужна память прошлой записи, а
  перенос в конец всего массива даёт тот же порядок без неё.

### 2. `Lampa.Recomends.get` и `page` читают списки типа

При установке патча `Lampa.Recomends.get(type)` заменяется функцией, которая берёт список типа
(`type == 'tv'` — сериалы, иначе фильмы, ровно как `get$4`: его зовут и другие плагины),
переворачивает его (последние первыми, как ядро) и убирает просмотренное. `Lampa.Recomends.page`
заменяется копией `page` ядра над новой `get` (тот же срез по 20, `empty({status: 404})`, заголовок
`Lampa.Lang.translate('title_recomend_watch')`). У замены `get` есть метка `__kp_split = true`: по ней
живая проверка отличает её от функции ядра. `recsRow` и «Ещё» не меняются: они уже зовут
`Lampa.Recomends.get` и `Router.call('recomend', …)`, а экран зовёт `Lampa.Recomends.page`
(Context). Плагин `kp_source` на вкладках «Фильмы»/«Сериалы» тоже читает `Lampa.Recomends.get` и
получит те же списки.

Просмотренное — множество `recKey(id, isTv)`: записи истории `tmdb`/`cub` с их типом плюс найденные
TMDB-тайтлы KP-истории (то же множество `watched`, что уже строит `applyRecs`). Ядро сравнивает только
`id`. Сравнение по id и типу оставляет сериал, у которого id совпал с просмотренным фильмом. История
читается на каждый вызов `get`, как у ядра: просмотренное сразу пропадает из рядов.

Множество KP-тайтлов готово только после прохода по KP-истории. До конца прохода `get` фильтрует по
истории `tmdb`/`cub`. Ряды Главной и так ждут конца прохода (spec «Без просмотренного в рядах»).

Отвергнуто: «писать отфильтрованные списки обратно в `recomends_list`». Ядро обрежет их до 100
общих на следующем скане — ровно то, что чиним.

### 3. Проверка функций ядра

`Lampa.Recomends.page` добавляется в существующую проверку `recsMissing` рядом с
`Recomends.get`, `Router.call`, `Arrays.shuffle`. Нет любой — `recsFailed` (`Noty` и
`console.error`), замена `get`/`page` не ставится, ряды не строятся, как сейчас.

### 4. Лимит списка типа — 500, ошибка записи видна

Наблюдение на приставке 2026-11-21 после пина ветки с лимитом 100 (`main-recs.sh` → OK): в списке
фильмов 39 тайтлов, почти все — ужасы и зомби с оценкой 5.8–6.7 («Новая эра Z», «Обитель зла 3»,
«Понтипул», «Проклятие Чаки»). Запрос TMDB `movie/<id>/recommendations` по всем 33 фильмам очереди
`recomends_scan` (тем же фильтром года и истории, что у ядра) дал 398 уникальных тайтлов, по 8–19 на
фильм. В конце очереди стоят «Обсессия», «Одиссея», «Миньоны и монстры», «Бугония», «Иллюзия обмана 3»,
рождественская мелодрама 895954, детский сборник 1513703, «На краю Оук-стрит», «Зловещие мертвецы:
Пекло», «Обитель зла». Ядро идёт по очереди с начала (`ids[0]` из `!e.scan`), поэтому к концу круга
100 последних — рекомендации 5–7 последних фильмов очереди, то есть ужасы и детское, а рекомендации
«Бойцовского клуба», «Остров проклятых», «Трои» из начала очереди вытеснены.

Лимит — 500 на тип: столько держит круг из ~400 уникальных фильмов с запасом. Тайтл в Storage —
~790 символов (замер `JSON.stringify(kp_recs_movie).length / length`), 2 × 500 — ~0.8M символов при
занятых 0.43M во всём `localStorage` и квоте WebView ~5M. `Storage.set` ядра при переполнении пишет
только `console.log` и зовёт `callerror`, если он передан. Плагин передаёт `callerror` с
`console.warn('kp-reactions-fix: recommendations: <ключ> not saved', e.name)`, иначе список молча не
сохранялся бы между запусками. Ряд по-прежнему берёт 40 случайных, теперь из всего круга.

Отвергнуто: «без лимита». Очередь ядра держит до 300 тайтлов (`Storage.cache('recomends_scan', 300)`),
это до 6000 рекомендаций (~4.7M символов) — на грани квоты. «Ранжировать по числу фильмов истории,
которые рекомендуют тайтл». Это не фильтр по просмотренному, а пользователь выбрал только его.

## Risks / Trade-offs

- [История растёт: при больше ~25 фильмов с полными 20 рекомендациями первые сканы круга снова
  вытесняются] → Сейчас 398 из 500. Предупреждения нет — потеря постепенная, не сбой; лимит поднять
  при следующем пересмотре, замер выше показывает запас по квоте.
- [Список фильмов на приставке растёт постепенно: ядро сканирует один тайтл раз в 120 с, пока окно
  видно, полный круг очереди из 62 тайтлов — около 2 часов на экране] → Сразу после установки ряд
  фильмов тот же (15 тайтлов). Живая проверка смотрит только «не меньше, чем в списке ядра».
- [Новая версия ядра перестанет звать `page` через объект или переименует ключ] → «Ещё» покажет
  список ядра, ряды — списки плагина. Ловец — `main-recs.sh` (задача 5.1): оборачивает
  `Lampa.Recomends.page` счётчиком вызовов перед «Ещё» и требует вызова с `media` `tv` и числа
  страниц по `get('tv')`. Сравнение первой страницы с `get` этого не поймало бы: хвост списка
  сериалов совпадает со списком ядра. Ловит при смене пина; другого ловца нет, ядро обновляется само.
- [Копия `page` в плагине разойдётся с контрактом экрана ядра (поля ответа, `empty`)] → Тот же ловец:
  экран «Ещё» открывается и вызывает замену, тест «recs page slices list» держит срез и пустой ответ.
- [`Lampa.Recomends.get` меняется глобально, его видит и `kp_source`] → Это желаемо: те же списки на
  вкладках «Фильмы»/«Сериалы».
- [Ключи `kp_recs_*` весом до ~200 объектов TMDB в localStorage] → Тот же порядок, что
  `recomends_list` ядра.

## Migration Plan

После merge в `main` пин `kp-reactions-fix.js` на приставке переводится на новый sha, со снапшотом по
`docs/snapshots-convention.md`. При первом запуске списки типа заполняются из `recomends_list`.
Откат — прежний sha; ключи `kp_recs_movie`/`kp_recs_tv` прежний плагин не читает, их можно удалить
или оставить.
