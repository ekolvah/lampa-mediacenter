## Purpose

Плагин `kp-reactions-fix.js` включает тайтлы, запущенные с KP-карточек, в ряд «Рекомендуем посмотреть»
ядра Lampa наравне с историей источников `tmdb` и `cub`. Уже просмотренное через KP в этот ряд не попадает.

## ADDED Requirements

### Requirement: KP-история в очереди рекомендаций
Для каждой записи истории с источником `KP` плагин SHALL искать TMDB-тайтл тем же способом, что для
трейлеров KP-карточки (spec `kp-card-trailers`). Тип записи (сериал, если есть `number_of_seasons` или
`first_air_date`, иначе фильм) SHALL задавать тип поиска. Каждый найденный тайтл, которого ещё нет в
очереди сканирования ядра (`recomends_scan`), SHALL вставать в её начало в форме записи ядра: TMDB id и
признак сериала. Записи, которые уже есть в очереди, их порядок и отметки сканирования SHALL оставаться
как были. Плагин SHALL искать записи по одной и делать это один раз за запуск, когда приложение готово.
Вставленные записи SHALL сохраняться, когда ядро потом перезаписывает очередь, и после перезапуска.
Если первая после вставки запись очереди ядром не содержит вставленных записей, плагин SHALL писать
`console.warn` с префиксом плагина.

#### Scenario: KP-фильм
- **WHEN** в истории есть KP-фильм, для которого найден TMDB-фильм 550, а в очереди его нет
- **THEN** первой записью очереди становится фильм 550 без признака сериала

#### Scenario: KP-сериал
- **WHEN** в истории есть KP-запись с `number_of_seasons`, и по её `imdb_id` TMDB находит и фильм, и сериал 1399
- **THEN** в начале очереди есть запись 1399 с признаком сериала

#### Scenario: Очередь ядра не тронута
- **WHEN** в очереди уже есть записи ядра, одна из них — найденный для KP-записи тайтл с отметкой сканирования
- **THEN** второй записи для этого тайтла не появляется, а записи ядра идут в прежнем порядке и с прежними отметками следом за вставленными

#### Scenario: Один раз, когда приложение готово
- **WHEN** плагин загружен до события `app` `ready`, а потом событие приходит дважды
- **THEN** до события запросов поиска нет, после него KP-записи ищутся по одной и очередь пишется один раз

#### Scenario: Ядро перезаписывает очередь
- **WHEN** после вставки ядро записывает очередь из своего массива, полученного при старте
- **THEN** вставленные записи есть в записанной очереди

#### Scenario: Ядро подменило очередь
- **WHEN** после вставки ядро записывает очередь, в которой вставленных записей нет
- **THEN** в консоли есть предупреждение с префиксом плагина о том, что ядро переписало `recomends_scan`

#### Scenario: Очередь на приставке
- **WHEN** Lampa на приставке запущена с новым плагином и показывается дольше 120 с
- **THEN** в начале `recomends_scan` стоят TMDB id KP-тайтлов истории, первую из них ядро отмечает отсканированной, в `recomends_list` нет тайтлов KP-истории, и после перезапуска процесса записи на месте

### Requirement: Просмотренное через KP не в ряду
Плагин SHALL убирать из списка рекомендаций ядра (`recomends_list`) тайтлы, у которых TMDB id и тип
(сериал, если есть `number_of_seasons` или `first_air_date`) совпадают с найденным TMDB-тайтлом
KP-записи истории. Это SHALL делаться, когда приложение готово, и после каждой записи списка ядром
в этом запуске. Остальные записи списка SHALL оставаться в прежнем порядке.

#### Scenario: Просмотренный KP-фильм убран
- **WHEN** в списке рекомендаций есть фильм 550 среди других, а в истории есть KP-фильм, для которого найден фильм 550
- **THEN** фильма 550 в списке нет, остальные записи в прежнем порядке

#### Scenario: Тот же id у другого типа
- **WHEN** в списке есть сериал с id 550, а KP-история дала фильм 550
- **THEN** сериал 550 остаётся в списке

#### Scenario: Рекомендация пришла позже
- **WHEN** в этом запуске ядро записывает в список фильм 550, а KP-история дала фильм 550
- **THEN** после записи ядра фильма 550 в списке нет

#### Scenario: Убирать нечего
- **WHEN** приложение готово, а в списке нет тайтлов KP-истории
- **THEN** плагин список не перезаписывает

### Requirement: Ненайденная KP-история видна
Когда для KP-записи истории TMDB-тайтл не найден, поиск не удался или проход не дошёл до неё за 60 с,
плагин SHALL пропускать её и
SHALL писать `console.warn` с числом пропущенных записей из общего числа KP-записей. Остальные записи
SHALL обрабатываться как обычно.

#### Scenario: Тайтл не найден или TMDB не ответил
- **WHEN** из четырёх KP-записей истории для одной TMDB-тайтл не найден, а для другой запрос `find` завершился ошибкой
- **THEN** две другие встают в очередь, а в консоли есть предупреждение с префиксом плагина и текстом `2 of 4`

#### Scenario: Проход не успел
- **WHEN** ответ на поиск второй из трёх KP-записей не пришёл за 60 с
- **THEN** очередь пишется по первой записи, а в консоли есть предупреждение с текстом `2 of 3`
