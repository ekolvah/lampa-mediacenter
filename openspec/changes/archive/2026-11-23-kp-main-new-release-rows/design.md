## Context

`kp-reactions-fix.js` уже оборачивает `KP.main` (`mainPortion`): зовёт `kp_source`, в его первой
порции заменяет ряды «Сейчас смотрят» новинками (`filterRows`), ставит за ними ряды рекомендаций
(`addRecs`) и отдаёт порцию не позже `ROWS_TIMEOUT_MS = 5000`. Подгрузку `kp_source` обёртка не
трогает, и через неё приходят остальные 9 рядов `kp_source`. Плагин, таким образом, правит чужую
Главную снаружи, и каждое её изменение у `kp_source` — новый особый случай у нас.

## Standard approach

**`kp_source`** (`https://nb557.github.io/plugins/kp_source.js`, скачан 2026-11-23). `main$1`:
`parts_limit = 5`, `parts_data` — `TOP_POPULAR_MOVIES` («Сейчас смотрят фильмы»), `POPULAR_SERIES`,
`TOP_250_MOVIES` («Топ фильмы»), `TOP_250_TV_SHOWS`, затем
`api/v2.2/films?order=NUM_VOTE&type=FILM|TV_SERIES|MINI_SERIES|TV_SHOW` («Популярные …»), а после
`menu()` в позиции 5/7/9 — те же запросы с `&countries=<id «Россия»>`. Возвращает `loadPart` над
`Lampa.Api.partNext(parts_data, parts_limit, …)`, но первую порцию грузит только после ответа
`menu()`. Каждый ряд — `getList('<url>', params, function (json) { json.title = '<заголовок>';
call(json); })`, а `list(params)` для такого `url` — тот же `getList(params.url, params, …)`: ряд
Главной `kp_source` — это ответ `KP.list` 1-й страницы плюс заголовок. Его же `category()` строит на вкладках ряд «За
год»: `'api/v2.2/films?order=NUM_VOTE' + filter + '&yearFrom=' + yearFrom + '&yearTo=' + yearTo`, где
жанр — `'&genres=' + genres_map['мультфильм']`, а `genres_map` заполняет `kpFilters()` из
`api/v2.2/films/filters` (`genres_map[g.genre] = g.id`). Это и есть образец запроса рядов новинок.

  this.empty.bind(this)); if (typeof nextCall == 'function') next = nextCall;`, `onNext(resolve,

## Goals / Non-Goals

**Goals:** на Главной KP после рекомендаций только ряды новинок (топ по типам и 10 жанров), без
повторов тайтлов между рядами Кинопоиска.

**Non-Goals:**
- Повторы между рядами рекомендаций (`tmdb`) и рядами Кинопоиска: id разных источников, сопоставление
  — поиск TMDB-тайтла на каждую карточку.
- Чистка повторов в полном списке «Ещё».
- Вкладки «Фильмы»/«Сериалы» (`KP.category`) — не трогаются.
- Настройка набора рядов из интерфейса: набор — константа плагина.

## Decisions

### 1. Главную KP строит плагин, `KP.main` `kp_source` не зовётся

Обёртка `KP.main` больше не зовёт `orgMain`. Первая порция: для каждого ряда `NOW_WATCHING` —
`orgList` 1-й страницы его коллекции (заголовок — из `NOW_WATCHING`, как у `kp_source`), дальше
прежние `collectPages` с этим ответом как `known`, `filterRows` и `addRecs`, который дописывает
рекомендации в конец (`recsIndex` с его особым случаем не нужен). Параллельно с 1-ми страницами
зовётся `KP.menu` (решение 3). Всё под одним `waiter` на `ROWS_TIMEOUT_MS` от вызова `KP.main`. Не
пришла 1-я страница коллекции — ряда нет, `console.warn` с названием и причиной, как у ряда
новинок; не пришли обе — `rowsFailed` с причиной: это смена `url` коллекций у Кинопоиска, и иначе её
до следующего пина было бы не видно. Путь `rowsFailed('no row …')` удаляется — «`kp_source` не
отдал ряд» больше не бывает. Затем Главной уходит своя подгрузка (решение 4).

`menu()` у `main$1` зовётся до рядов (kp_source.js:504) и заполняет `genres_map` (:844), а
`convertElem` берёт из него `genres[].id` (:218, иначе 0). Без `orgMain` карточки «Сейчас
смотрят» первой после запуска Главной могут успеть сконвертироваться до ответа `KP.menu` и получить
`id` 0. Принято: карточка фильма грузится заново через `KP.full` (kp_source.js:633), а кэш `getList`
хранит сырой ответ, не карточки (:385–390). Ряды подгрузки идут после первой порции, когда ответ
`KP.menu` уже пришёл или истёк.

Короткая первая порция — как у `partNext` ядра (app.min.js:44037, `data.length < 3` → склеить со
следующей порцией): ядро грузит следующую порцию, только если на Главной есть ряды
(`onLoadNext`, `this.items.length`, app.min.js:44439), а без них Главная осталась бы пустой.
Поэтому первая порция меньше 3 рядов дописывается порциями подгрузки, пустая и после этого —
`onerror` `KP.main` (экран «пусто» ядра).

Так у Главной один источник правды — таблица рядов плагина: `kp_source` даёт только `KP.list`
(запрос, кэш, CORS-прокси при 429, `convertElem`) и `KP.menu`. Первая порция ждёт `menu()` вместе с
рядами, а не до них, и не тянет 3 ряда, которые выбросили бы.

Отвергнуто: оставить `orgMain` и выбрасывать из его порции всё, кроме «Сейчас смотрят» — 3 лишних
запроса и ожидание `menu()` до первой порции, а раскладка `kp_source` остаётся посылкой, которую
надо проверять (`rowsFailed` при пропаже ряда); свой форк `kp_source` — хостить и сверять с
апстримом (правило «сначала готовое» в CLAUDE.md); фильтр поверх подгрузки `kp_source` — она всё
равно запросит 9 лишних рядов; `ContentRows` — `kp_source` его не зовёт (design.md
`kp-main-recommendations`).

### 2. Запрос — `films?order=NUM_VOTE` с годом, как «За год» у `kp_source`

Окно — `yearFrom = Y−1`, `yearTo = Y`: то же, что `noveltyRule().minYear` рядов «Сейчас смотрят»,
чтобы «новинка» значила одно на всей Главной. Окно «За год» у `kp_source` (`Y − (month < 6)`) во
второй половине года сужается до текущего года — тогда в ноябре в топе только тайтлы с начала года.
`order=RATING` и тематические коллекции отвергнуты по наблюдениям выше: первый даёт тайтлы с
единицами оценок, вторые — старые и без фильтра по году.

### 3. Жанр — по названию из `KP.menu`

id берётся из `KP.menu` по названию, как `genres_map` у самого `kp_source`. `kpFilters` держит
список в памяти страницы: запрос `api/v2.2/films/filters` один на запуск Lampa. Зашитый
id при перенумерации у Кинопоиска молча дал бы ряд не того жанра (§IV); пропавшее название видно —
ряда нет, `console.warn`. Нет `KP.menu` — изменился сам `kp_source`, поэтому жанровых рядов нет, а
причина видна на экране: `missingFns(['Api.sources.KP.menu'])` и `rowsFailed`, без своей пары
уведомление/ошибка. Отвергнуто: считать это «нет жанра» у каждого ряда — изменение `kp_source`
ушло бы только в консоль. Так же — если в списке `KP.menu` нет ни одного жанра таблицы: `kpFilters` у
`kp_source` при ошибке `api/v2.2/films/filters` отдаёт пустой список и ничего не кэширует, а при смене
формы ответа названия не совпадут; 10 предупреждений вместо уведомления скрыли бы ту же поломку.
Первый вызов на запуск идёт в сеть, поэтому ответ `KP.menu` ждёт `waiter` первой порции Главной
(решение 1, `ROWS_TIMEOUT_MS`): не пришёл — жанровых рядов нет, как при пустом списке.

### 4. Своя подгрузка вместо `Lampa.Api.partNext`

Наблюдение, приставка 2026-11-23 (`tools/cdp.py`): `Lampa.Api.partNext` с тремя рядами, ответы
через 300/100/200 мс — `order: "r1,r2,r3"`, порядок сохраняется; с рядом, который не отвечает, —
`hang: "no answer after 3s: waits forever"`. Одна зависшая выдача остановила бы всю Главную, а
повторы надо чистить после всех ответов порции, до решения о пустоте (`partNext` решает раньше и
склеивает порции при `data.length < 3`).

Своя подгрузка: следующие 5 рядов таблицы, каждый — один `orgList`-запрос страницы 1 (20 карточек,
как у ряда `kp_source`; API отдаёт не больше 5 страниц, `5p` во всех наблюдениях, это `total_pages`
для «Ещё»), общий `waiter` на `ROWS_TIMEOUT_MS`, затем ряды по порядку таблицы, чистка, пустые долой;
пустая порция — сразу следующая; рядов нет — `reject`. Порция в 5 рядов — как `parts_limit` у
`kp_source`. Подгрузка живёт, пока открыта Главная, поэтому держит только набор `id`, номер
следующего ряда таблицы и id жанров, найденные один раз, а не ответы первой порции.

Отвергнуто: `collectPages` для запроса ряда — он судит новизну каждой карточки и для сериалов со
старым стартом спрашивает TMDB о последнем эпизоде, а окно года здесь уже в самом запросе; запрос
следующей порции заранее — Главная зовёт подгрузку почти сразу, выигрыш мал, а лишние запросы
приближают 429.

### 5. Чистка повторов — набор `id` одной Главной

Набор заводится на вызов `KP.main`. В него идут карточки показанных рядов «Сейчас смотрят» (после
фильтра новинок), затем каждого ряда новинок по мере выдачи. Рекомендации (`tmdb`) не участвуют.
Каждое открытие Главной — новый набор.

## Risks / Trade-offs

- Ряды меняются медленнее, чем «Сейчас смотрят»: состав топа новинок зависит от прироста оценок, окно
  сдвигается раз в год. Принято: это самая подвижная выборка, которую даёт API без своей памяти.
- Число оценок Кинопоиска тянет вверх российское: топ новинок в основном российский. Принято:
  аудитория та же.
- 13 запросов при прокрутке Главной вместо 9: API отвечает 429 → `kp_source` уходит на свой
  CORS-прокси. Ряд без ответа за 5 с — `console.warn`, ряда нет.
- Улучшения Главной в `kp_source.main$1` до нас не дойдут: её раскладка теперь наша. Принято: ради
  этого и сделано. Зависимость остаётся на `KP.list` (как и у «Ещё» сейчас) и `KP.menu` (решение 3).
- Смена `url` коллекций «Сейчас смотрят» у Кинопоиска — оба ряда пропадут; это видно сразу:
  уведомление и `console.error` (решение 1). Пропажу одного ряда видно только по `console.warn` и
  по `now-watching.sh` при следующем пине.
