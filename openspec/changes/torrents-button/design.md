## Context

Поведение движка (`Torrents.onCreate`, меню «…» и событие `full`/`options`, `onGroupButtons`,
`collectionFocus`, порядок `complite` → `groupButtons` → `toggle`) и проба на приставке записаны в
proposal.md, раздел Why. Кнопка «Трейлер» уже живёт в `plugins/kp-reactions-fix.js`
(`addTrailerButton`, слушатель `full`/`complite`) и ставится через `.after()` за `.button--play`.

## Goals / Non-Goals

**Goals:** «Торренты» открывают список торрентов с одного OK. В строке кнопок нет «Смотреть», а в
меню «…» он есть.

**Non-Goals:** менять меню «Смотреть» и порядок его пунктов, список торрентов и путь серий
(`emit('watch', {season})`). Не трогать `full_btn_priority`: если пользователь сам выставит
приоритет, клон движка встанет перед нашими кнопками, и это допустимо. Не поддерживаем
`lampa_settings.read_only`: на приставке он выключен.

## Decisions

### 1. Своя кнопка «Торренты», а не штатный `full_btn_priority`

Кнопка находит источник селектором `.view--torrent:not(.hide)` и передаёт ему нажатие
(`torrent.trigger('hover:enter')`). Тот же вызов делают меню «Смотреть»
(`a.btn.trigger('hover:enter')`) и клон приоритета. Поиск, `Activity.push` и сезон остаются в
движке. `hide` с `.view--torrent` движок снимает только при `parser_use`, и делает это в `onCreate`,
то есть до `complite` (proposal.md, Why).

Альтернатива — штатный приоритет кнопки, то есть настройка вместо кода. Отклонена. Движок узнаёт
кнопку по хэшу всей её разметки, а Lampa обновляется с `lampa.mx` без нас: `v=1994234` 2026-11-16,
`v=1994469` 2026-11-18. Правка шаблона молча сбросит приоритет. Пока «Смотреть» в строке, это стоит
одного нажатия. Без «Смотреть» торренты ушли бы на три («…» → «Смотреть» → «Торренты»), и никто бы
этого не заметил (§IV). Класс `view--torrent` стабилен: на нём держатся шаблон и код самого движка
(`Torrents.onCreate`, `onPriorityButton`).

### 2. Один слушатель `full`, кнопки встают на место «Смотреть»

`startPlugin` регистрирует один `Lampa.Listener.follow('full', onFull)` вместо `addTrailerButton`.
`onFull` только разбирает `e.type`:

- `complite`: один раз находит `play` и название, без `play` пишет одно предупреждение и выходит.
  Иначе собирает свои кнопки по порядку: «Торренты», если есть источник, затем «Трейлер», если есть
  `.view--trailer`. Ставит их за `play` и удаляет его: `play.after(buttons).remove()`. Порядок кнопок
  задаёт массив, а не очерёдность нескольких вставок или `follow`.
- `options`: пункт «Смотреть» (решение 4).

Разметку обеих кнопок делает общий `cardButton(cls, sprite, text, onEnter)`:
`div.full-start__button.selector.<cls>` со `<svg><use xlink:href="#sprite-…">` и `<span>`. Спрайт
торрентов — `#sprite-torrent` из шаблона `.view--torrent`. Обработчики замыкают только найденный
элемент движка и название, а не `e` (так `body` и `data` события не живут вместе с кнопкой).

Альтернатива — ставить кнопки в начало `.full-start-new__buttons`, тогда они не зависят от
«Смотреть». Отклонена: без `.button--play` шаблон карточки уже не тот, что мы видели, и молча
вставлять в него кнопки хуже, чем предупредить (§IV). Предупреждение у «Трейлера» уже такое.

### 3. «Смотреть» удаляется из DOM, а не скрывается

Класс `hide` не годится: `onGroupButtons` при каждом `toggle` карточки делает
`play.toggleClass('hide', …)` и вернёт кнопку (proposal.md, Why). Удаление — путь самого движка для
`read_only`, и его код кнопок работает с пустой выборкой `play`. CSS `display:none` тоже отклонён:
`collectionFocus` проверяет `offsetParent` только у `last`, а запасной фокус ищет первый `.selector`
без класса `hide`, поэтому может встать на невидимую кнопку.

Фокус после открытия: `collectionFocus` без `last` берёт первый `.selector` карточки. После удаления
`play` это наша первая кнопка (порядок `.selector` — proposal.md, Why).

### 4. Пункт «Смотреть» в меню «…»

На `full`/`options`: `var link = e.link; e.options.push({title: 'Смотреть', onSelect: function () {
link.emit('watch', {}); }})`. Что `e.link` — карточка, что пункт встаёт первым и открывает меню
источников, проверено пробой (proposal.md, Why). `onWatch` сам решает: один источник запускает сразу,
иначе показывает список. Возврат из него ведёт в карточку. Пункт есть и без `play`: он зовёт `emit`, а
не кнопку.

### 5. Тесты

В `tests/js/kp-reactions-fix.test.js` двойники в памяти (§II, без моков логики). Двойник `e.body` в
`openCard()` получает `.view--torrent:not(.hide)` (`length`, `trigger` пишет вызов в `calls`), а у
`.button--play` — `after(buttons)` с `remove()`. Тесты пункта «Смотреть» вызывают `load()` и
`c.listeners.full({type: 'options', options: [], link: {emit}})` напрямую, без `openCard()`.
Существующий тест «no play button, warning» дополняется проверкой, что ничего не вставлено. Сценарии
с пульта проверяет живой шаг.

## Risks / Trade-offs

Оба риска — дрейф Lampa, которая грузится с `lampa.mx` вне репозитория. Как и у кнопки «Трейлер»,
его ловит пользователь, а затем `bash tests/live/kp-trailers.sh` при следующей правке плагина.
Плановой проверки нет: ежедневный прогон на приставке ради строки кнопок не окупается (цель 2).

- [Движок перестанет слать `full`/`options` или сменит форму `options`] → «Смотреть» пропадёт и из
  строки, и из «…». Торренты и трейлер останутся на кнопках, а онлайн-источники (Shots, Alpac) станут
  недоступны из карточки. Ловят пользователь и шаг `menu-focus` (путь «…» → «Смотреть» →
  «Трейлеры»).
- [Движок сменит класс `view--torrent`] → кнопки «Торренты» нет, торренты остаются в «…» →
  «Смотреть». Ловят пользователь и `openCard` (`tests/live/kp-trailers/lib.js`): он ждёт фокус на
  «Торренты» и падает первым, на шаге `open-card-no-imdb` у «Зверя».

Живые проходы делятся так: «Зверь» проходит кнопкой «Трейлер» и списком через «…» → «Смотреть» →
«Трейлеры» (это прежнее доказательство сценариев «Русский трейлер с пульта» и «Запуск трейлера
пультом»), «1+1» — «Торренты» и кнопкой «Трейлер». Путь через «…» проходится один раз за прогон.
