## Context

Как трейлеры попадают в KP-карточку и почему у «Джентльменов» играет 1-й сезон — proposal.md (две
причины, ответы TMDB). Библиотека `trailer-search` v0.2.0 уже умеет искать трейлер нужного сезона.

Наблюдения о движке, на которых стоят решения (2026-11-16, приставка, `cdp.py`, Lampa на переднем
плане):

- `Lampa.Api.sources.tmdb.videos` (исходник через `.toString()`) делает два запроса
  `get(params.method + '/' + params.id + '/videos', {langs: 'ru'})` и `{langs: 'en'}` с `life` 7
  дней и склеивает `results`. Отдельного пути для сезонов у движка нет.
- `tmdb.videos({method: 'tv/236235/season', id: 2}, cb)` отдаёт видео 2-го сезона из proposal.md.
  `tmdb.get('tv/236235/season/9/videos', {langs: 'en'})` (такого сезона нет) → успех, `results: []`,
  `onerror` не вызван.
- `tmdb.get` для пути с `tv/<id>/season/<n>` при ошибке зовёт внутренний `seasonFix`, а не
  `onerror`. `seasonFix` перезапрашивает тот же путь с `season/1` и ищет в ответе `episodes`
  (`Utils.splitEpisodesIntoSeasons(new_json.episodes)`). В ответе `…/videos` поля `episodes` нет,
  поэтому дальше будет либо `onerror`, либо исключение в колбэке, и тогда колбэк не придёт вовсе
  (исходник `seasonFix` из `app.min.js?v=1994251`, 2026-11-16).
- Список «Трейлеры» движок строит в `onCreate` карточки: `items.sort` с компаратором
  `a.time > b.time ? -1 : a.time < b.time ? 1 : 0`, где `time = new Date(published_at).getTime()`;
  затем `my_lang` (`code == Storage.field('tmdb_lang')`), разделитель «Ещё», `en`. При равных датах
  порядок задаёт стабильность `sort` в WebView, а она не проверена.
- Страница Lampa в фоне (`document.visibilityState` = `hidden`) не получает сетевые колбэки, и
  `cdp.py` упирается в таймаут. Живые шаги идут после `restart_lampa`.

## Goals / Non-Goals

**Goals:**

- У KP-сериала, у которого последний вышедший сезон N ≥ 2, первым в «Трейлерах» стоит трейлер
  сезона N: русский от сервиса, иначе трейлер сезона N из TMDB.
- `find` по `imdb_id` даёт тайтл того же типа, что и карточка.
- Фильмы и сериалы с одним сезоном работают как раньше.

**Non-Goals:**

- Карточки источника `tmdb`: плагин их не трогает, источник на приставке — `KP`.
- Трейлер сезона, который анонсирован, но ещё не вышел. «Последний сезон» — это сезон последней
  вышедшей серии.
- Удаление из списка роликов старых сезонов: они остаются после ролика сезона N.
- Структурный признак замены в библиотеке `trailer-search` (см. решение 5).

## Standard approach

- TMDB API:
  - https://developer.themoviedb.org/reference/find-by-id
  - https://developer.themoviedb.org/reference/tv-series-details (`last_episode_to_air`)
  - https://developer.themoviedb.org/reference/tv-season-videos

  Поля проверены ответами из proposal.md.
- Готовый чужой плагин: none found, не искали. Ошибка — в логике своего плагина поверх
  `kp_source`, чужой плагин её не заменит.

## Decisions

### 1. Тип карточки решает выбор в `find`

Если `find` вернул и `movie_results`, и `tv_results`, плагин берёт результат того же типа, что и
`movie.type` KP-карточки (`tv` → сериал, иначе фильм). Если результата нужного типа нет, берётся
тот, что есть, как сейчас. Если `find` ничего не вернул, плагин ищет по названию.

Альтернативы:

- **Отбрасывать «пустые» записи TMDB** (без даты выхода, 0 голосов). Это эвристика по косвенным
  признакам, а тип карточки известен точно.
- **При несовпадении типа искать по названию.** Тогда тайтл, у которого типы в KP и TMDB
  расходятся (например, мини-сериал, который KP считает фильмом), потеряет верный результат `find`.
  Поиск по названию идёт по типу карточки и такой тайтл не найдёт.

### 2. Номер последнего сезона — из `tv/<id>` TMDB, параллельно с видео

Для тайтла `tv` плагин запрашивает в `enrich` `tmdb.get('tv/<id>')` с `life` в один день. Запрос
идёт одновременно с видео и реакциями: существующий счётчик `pending` для сериала равен 3. Решение о
трейлере принимается, когда пришли и видео, и сведения о сериале.

- N = `last_episode_to_air.season_number`, дата = `last_episode_to_air.air_date`.
- Если N < 2, всё идёт как раньше.
- Если запрос не удался или поля нет, плагин пишет предупреждение с id сериала и тоже действует как
  раньше.

Альтернативы:

- `number_of_seasons`: у «Джентльменов» он равен 3, потому что 3-й сезон объявлен без даты.
- `movie.seasons` от `kp_source`: их содержимое не проверяли.

Кэш на день, а не на неделю, как у `find`: новый сезон должен подхватиться быстро.

### 3. Сервис всегда спрашивают про сезон N

При N ≥ 2 плагин спрашивает сервис с `season=N`, даже если в видео TMDB есть ролики на `ru`: по
ним нельзя понять, к какому сезону они относятся.

Альтернатива — считать «своим» русский ролик TMDB, опубликованный после выхода сезона N. Это не
работает, потому что трейлеры выходят до премьеры. Русский трейлер 1-го сезона «Джентльменов»
опубликован 2024-02-26, а сезон вышел 2024-03-07 (proposal.md).

### 4. Один путь вставки; без ролика сервиса — трейлер сезона N из TMDB

Ролик ставит первым одна функция, и для ответа сервиса (фильмы тоже), и для ролика TMDB:

- `iso_639_1` = `Lampa.Storage.field('tmdb_lang')`: движок кладёт видео на этом языке до
  разделителя «Ещё»;
- `published_at` = дата сезона N (для фильма — дата выхода), но не раньше чем через секунду после
  самого нового `published_at` в списке. Строго позже, а не «не раньше», потому что при равных
  датах порядок не гарантирован (Context).

Если сервис ролик не дал (`video_id: null`, ошибка, таймаут), плагин берёт видео сезона тем же путём,
что и движок: `tmdb.videos({method: 'tv/<id>/season', id: N}, cb)`. Из них берётся самый новый
`Trailer`. Он вставляется той же функцией, а в консоль пишется предупреждение с названием, N и
причиной. Если трейлера нет, список остаётся как есть, а в консоль пишется предупреждение с названием
и N. Ответ, не похожий на `{results: [...]}`, считается пустым списком.

Колбэк `tmdb.videos` для сезона может не прийти (`seasonFix`, Context). Поэтому на ожидание стоит
тот же предел, что и на сервис (`TRAILER_TIMEOUT_MS`, 10 с). По его истечении плагин идёт дальше,
как при пустом списке, и пишет предупреждение. Поздний колбэк игнорируется.

Тизер вместо трейлера не берётся: пользователь выбрал трейлер сезона (proposal.md), а запасной
вариант для запасного варианта — лишняя ветка.

Метка языка у английского ролика — неправда в данных, но поставить его выше русских иначе нельзя.
Пользователь выбрал, что сезон важнее языка (proposal.md).

Видео сезона запрашиваются только после отказа сервиса, а не параллельно с ним. Отказ — редкий путь,
а параллельный запрос ради него стоил бы двух лишних запросов к TMDB на каждый сериал.

### 5. Сервис: параметр `season`; ролик другого сезона — «не найден»

- `parse_query` читает `season` тем же способом, что и `year`: общая функция разбора целого
  параметра, которая для `season` требует значение ≥ 1. Иначе `BadRequest` → 400.
- `TrailerQuery` получает поле `season`. Кэш хранит ответы по `TrailerQuery`, так что `season`
  попадает в ключ кэша.
- `LibraryFinder` передаёт `season` в `FilmProfile`. Если `reason` выбора кончается на
  `; season {N} fallback`, сервис отвечает `video_id: null`, `title: null` с тем же `reason`.

Сервис отвечает на вопрос «трейлер сезона N». Ролик другого сезона — не ответ на этот вопрос.

Признак замены есть только в тексте: у `TrailerPick` в v0.2.0 нет отдельного поля
(`strategy.py:158` на теге). Альтернатива — отключаемая замена или поле в библиотеке, но это ещё
один выпуск `trailer-search`. Риск описан в «Risks».

## Risks / Trade-offs

- **Библиотека сменит текст `; season N fallback`.** Тогда ролик другого сезона пройдёт как ролик
  сезона N, и первым снова встанет старый сезон — тот же баг, что и сейчас. Тесты сервиса его не
  поймают: они закрепляют текст v0.2.0, но работают с фейковой библиотекой. Ловит
  `tests/live/kp-trailers.sh`: шаг `open-card-season` требует, чтобы в названии первого ролика
  «Джентльменов» был 2-й сезон. Рядом с пином в `tools/trailer-search.requirements.txt` стоит
  комментарий, что после поднятия пина этот скрипт обязателен. Полностью риск закроет структурный
  признак замены в `trailer-search`. Issue на него открывается в задаче 2.3, ссылка ставится здесь и
  у проверки суффикса в `tools/trailer_service.py`.
- **Карточка сериала с N ≥ 2 открывается дольше:** сервис теперь ищет трейлер и там, где раньше
  хватало русского ролика TMDB. Промах кэша сервиса — ~2,8 с, попадание — ~0,1 с (замер в
  `docs/jacred-on-ugoos.md`). Запрос `tv/<id>` идёт параллельно с видео и не добавляет задержки.
  Худший случай — около 20 с: сервис не ответил за 10 с, и запрос видео сезона тоже упёрся в свой
  предел (решение 4). Это цена последовательного запроса видео сезона. Такое бывает, только когда
  лежат и сервис, и TMDB, и оба случая видны предупреждениями.
- **Сервис старой версии** (до выкладки) не знает `season` и отдаёт ролик без учёта сезона. Поэтому
  выкладка идёт в порядке, описанном ниже.

## Migration Plan

1. Снапшот по `docs/snapshots-convention.md`.
2. Сервис:
   1. `adb push` нового `tools/trailer_service.py` и `tools/trailer-search.requirements.txt`.
   2. `pip install -r` в venv.
   3. Рестарт сервиса. Команды для всех трёх шагов — в `docs/jacred-on-ugoos.md`.
   4. Проверка в chroot:
      `curl '…/trailer?title=Джентльмены&original_title=The%20Gentlemen&year=2024&season=2'` → ролик
      2-го сезона.
3. Плагин: URL на приставке переключается на sha головы ветки, затем `bash tests/live/kp-trailers.sh`.
4. После мержа URL переключается на sha `main`, со снапшотом.

Откат — вернуть из снапшота прежний sha плагина, прежний `trailer_service.py` и пин `v0.1.0`, затем
`pip install` и рестарт сервиса. Новый плагин со старым сервисом работает безопасно: `season`
игнорируется, и поведение как до исправления причины 2.
