## Context

`kp-reactions-fix.js` уже подменяет на Главной `KP` штатные ряды «Сейчас смотрят» отфильтрованными:
`filterRows` → `collectPages` → `filteredRow` (spec `now-watching-new-releases`). Ряд идёт в порядке
коллекции. Issue #79 просит ставить новые тайтлы в начало ряда и оставляет открытыми четыре
вопроса: N дней, сезон сериала, что считать «открыли» и срок чистки.

## Standard approach

Готового решения нет (proposal.md, «Standard approach»). Ниже наблюдения о платформе, на которых
стоят решения. Источник — `https://nb557.github.io/plugins/kp_source.js`, скачан 2026-11-21:

- id карточки ряда — `"id": SOURCE_NAME + '_' + kinopoisk_id` в `convertElem` (`kp_source.js:206`),
  т. е. `KP_<n>`. Тем же `convertElem` строится и `movie` полной карточки.
- `full(params)` берёт тайтл из `params.card`: `if (params.card && params.card.source === SOURCE_NAME)
  { … startsWith(params.card.id + '', SOURCE_NAME + '_') …}` (`kp_source.js:639-643`). Значит, при
  открытии карточки `KP.full` получает тот же `id`, что был у карточки в ряду.
- Номер сезона в карточке коллекции не приходит. `number_of_seasons` появляется только у полной
  карточки, из отдельного запроса `api/v2.2/films/<id>/seasons` (`kp_source.js:270-273`, `:422`).

`Lampa.Storage.get/set` с объектом на ключ плагин уже использует для `recomends_scan`
(design.md изменения `kp-history-recommendations`).

## Decisions

### 1. Память ряда: один ключ, запись на id

Ключ `Lampa.Storage` `kp_now_watching_seen`: `{ <url ряда>: { <id карточки>: { f, s, l } } }`.

- `f` — время появления в мс. `0` значит «не новая»: так записываются карточки первого запуска и
  открытые.
- `s` — сезон сериала или `null`.
- `l` — день (номер дня от эпохи) последней сборки, где карточка была в ряду.

Ключ по id, а не по «id + сезон», как предлагало issue: у сериала одна запись, а правило «сезон
больше запомненного» покрывает и случай, когда сезон раньше был неизвестен. `f` — в мс, потому что
первой должна идти карточка, появившаяся последней, а за день их может быть несколько. `l` — в днях:
для чистки за 30 дней этого хватает, и ключ не меняется от сборки к сборке в один день (решение 6).
Отдельной отметки «открыт» нет: `f = 0` уже означает «не новая», а новый сезон ставит `f = now`.

«Сейчас» — тот же `new Date()`, который `filterRows` уже берёт для `noveltyRule`. Тесты подменяют
только конструктор `Date` (`FakeDate`), а `Date.now()` там идёт по реальным часам.

Значение не той формы (не объект, у ряда не объект) → `console.warn` и пустая память, т. е. первый
запуск (§VI).

### 2. Порядок — отдельная чистая функция, N = 5 дней

`orderByNovelty(results, rowMemory, seasons, now)` → `{ results, memory, changed }`. Её зовёт
колбэк завершения в `filterRows` для каждого ряда до `filteredRow`. `collectPages` и `filteredRow`
не меняются: фильтр и форма ряда отдельно, порядок отдельно. `listBatch` (полный список) функцию
не зовёт, поэтому «Ещё» остаётся в порядке коллекции. Утверждение design.md `now-watching-replace-rows`,
что «страница 1 совпадает с рядом на Главной», теперь верно только по составу.

Карточка новая, если `f > 0` и `now − f < 5 дней`. Новые идут первыми, по `f` по убыванию;
сортировка устойчивая, поэтому при равном `f` сохраняется порядок коллекции. Остальные идут за
ними в порядке коллекции. 5 дней предложило issue: при паре заходов на Главную в неделю тайтл
успеют увидеть в начале ряда, и ряд не забивается.

### 3. Сезон сериала: TMDB, только для уже запомненных

Сезон — `last_episode_to_air.season_number` из `tv/<id>` (кэш 1 день). Его отдаёт `lastSeason`,
тайтл ищет `resolveTitle`, как для трейлеров. Правило — требование «Новый сезон сериала».

- Сериал стартовал раньше прошлого года. `lastEpisode` уже зовёт `lastSeason` ради даты и теперь
  отдаёт `{ number, date }`. `collectPages` кладёт номер в `item` рядом с вердиктом. Новых
  запросов нет.
- Сериал стартовал не раньше прошлого года и уже есть в памяти ряда: сезон спрашивает
  `collectPages` в `addPage`, под тем же `pending()`. Для этого у неё появляется необязательный
  аргумент `needSeason(card)`: `filterRows` передаёт его по памяти ряда, `listBatch` не передаёт.
  Спрашивать сезон из `filterRows` после сбора страниц нельзя: `waiter`
  (`kp-reactions-fix.js:320-348`) зовёт `done`, как только пришёл последний ответ, и `pending()`
  после этого уже не действует. С аргументом на всю Главную остаётся один таймер `ROWS_TIMEOUT_MS`.
- Сериала нет в памяти, или нет памяти ряда: сезон не нужен. Сериал и так новый либо записывается
  при первом запуске с `s: null`. Номер узнается при следующей сборке.

Если сезон запомненного сериала не получен, пишется одно `console.warn('kp-reactions-fix: season
unknown', name, reason)`. `reason` — та же строка, что `lastEpisode` уже отдаёт для «new release not
checked». На тот же сбой уже пишут свои предупреждения `resolveTitle` и `lastSeason`
(`kp-reactions-fix.js:158`, `:229`, `:262`), а у старого сериала есть ещё и «new release not checked».
Их набор не меняется. Требование ограничивает только число предупреждений «season unknown»: одно на
сериал.

**Отвергнуто — сезон из КП `films/<id>/seasons`.** Это отдельный запрос на каждый сериал к КП-API
с общими ключами `kp_source` и лимитом 429. К тому же там есть и анонсированные сезоны: нужен ещё
фильтр по датам эпизодов. TMDB-путь уже есть и закэширован.

**Отвергнуто — без сезона для новых сериалов.** Сериал 2025 года со вторым сезоном в 2026 — частый
случай, и issue просит именно его.

**Отвергнуто — сезон в фоне, без ожидания Главной.** Тогда подъём по новому сезону приходит на
сборку позже, а запись памяти из фонового ответа гонится с записью при сборке. Ожидание уже
ограничено теми же 5 с, а запросы идут только для сериалов, которые есть в памяти (R18).

### 4. «Открыли» = `KP.full` с `params.card.id`

Обёртка `KP.full` уже есть. Сначала она зовёт `orgFull`, затем ставит `f = 0` по `params.card.id`
в рядах памяти и пишет ключ, если что-то поменялось. Так считается и открытие из поиска или
истории: тайтл посмотрели, поднимать его дальше незачем. Уже собранная Главная не перестраивается,
и карточка возвращается на место со следующей сборки. Lampa по «Назад» восстанавливает Главную без
`KP.main`, а перестраивать DOM ряда своими силами — лишний код ради редкого случая.

**Отвергнуто — «открыли» по истории Lampa (`Favorite.get({type: 'history'})`).** Пишет ли ядро
историю при открытии полной карточки, а не при запуске, не проверено. Кроме того, для нового сезона
нужно отличать открытие до подъёма от открытия после.

### 5. Первый запуск и неполный ряд

Нет записи ряда и `gaps === 0` → весь состав ряда пишется с `f = 0`. Нет записи и ряд неполный →
память ряда не пишется, порядок коллекции. Иначе карточки с недошедших страниц при следующей
сборке встали бы в начало как новые. Если запись есть, пропуски не мешают: у недошедших карточек
`l` не обновляется, а вернувшаяся карточка уже есть в записи.

### 6. Чистка и запись

При сборке из записи ряда удаляются id, у которых `сегодня − l > 30` дней. 30 дней покрывают
временный уход со страниц 1–5 и сбои загрузки. Ключ пишется одним `Storage.set` за сборку и только
если `orderByNovelty` хоть в одном ряду что-то поменяла: новый id, сезон, удаление или новый день в
`l`. Обычно это одна запись в день.

### 7. Видимость

- Сезон не получен — одно предупреждение с названием и причиной (решение 3, §IV).
- Испорченная память — `console.warn` с причиной (решение 1).
- `Storage.set` зовётся после `oncomplite(out)`: сбой записи памяти не задерживает и не ломает
  Главную. Исключения плагин не ловит.

## Migration Plan

После мержа: снапшот по `docs/snapshots-convention.md`, пин `kp-reactions-fix.js` на sha `main`.
При первом запуске нового плагина ряды записываются в память без подъёма карточек (решение 5).
Откат — пин прежнего sha. Ключ `kp_now_watching_seen` старый плагин не читает, удалять его не нужно.
