## ADDED Requirements

### Requirement: Поиск трейлера по названию
Сервис SHALL отвечать на `GET /trailer` с параметрами `title` (обязателен), `original_title` и
`year` (необязательны) JSON-объектом с полями `video_id`, `title`, `confidence` и `reason`. Ролик
SHALL выбираться библиотекой `trailer-search`. Если подходящего ролика нет, ответ SHALL быть
HTTP 200 с `video_id: null` и причиной в `reason`. Сервис SHALL слушать только `127.0.0.1`.

#### Scenario: Ролик найден
- **WHEN** приходит `GET /trailer?title=Зверь&original_title=The Beast&year=2026`, и поиск выбрал ролик
- **THEN** ответ HTTP 200, `video_id` и `title` этого ролика, `confidence` и `reason` выбора

#### Scenario: Ролик не найден
- **WHEN** поиск прошёл, но ни один ролик не подошёл
- **THEN** ответ HTTP 200, `video_id: null`, в `reason` причина

#### Scenario: Нет названия
- **WHEN** приходит запрос без `title` или с `year`, который не число
- **THEN** ответ HTTP 400 с описанием ошибки, поиска нет

### Requirement: Ошибка поиска видна
Ошибка поиска на YouTube SHALL NOT выглядеть как «ролик не найден». Она MUST давать HTTP 502
с полями `error` и `detail` и запись уровня ERROR в лог сервиса.

#### Scenario: YouTube отказал
- **WHEN** поиск на YouTube завершился ошибкой (например, YouTube счёл запрос ботом)
- **THEN** ответ HTTP 502 с `error` и текстом ошибки в `detail`, в логе ERROR с названием и годом

### Requirement: Кэш ответов
Успешный ответ (с роликом или с `video_id: null`) SHALL кэшироваться в памяти на 24 часа по
тройке `title`, `original_title`, `year`. Ошибка поиска SHALL NOT кэшироваться.

#### Scenario: Повторный запрос
- **WHEN** тот же запрос приходит повторно в течение 24 часов после успешного ответа
- **THEN** ответ совпадает с первым, поиска на YouTube нет

#### Scenario: Кэш истёк
- **WHEN** тот же запрос приходит позже чем через 24 часа
- **THEN** поиск на YouTube идёт заново

#### Scenario: Повтор после ошибки
- **WHEN** первый запрос получил HTTP 502, и тот же запрос приходит снова
- **THEN** поиск на YouTube идёт заново

### Requirement: Автозапуск
После загрузки приставки сервис SHALL подниматься сам, общим boot-хуком сервисов chroot.
Запуск SHALL быть идемпотентным, а неудачный старт MUST быть виден в логе boot-хука строкой
с именем сервиса и кодом возврата.

#### Scenario: После перезагрузки
- **WHEN** приставка перезагружена
- **THEN** `GET http://127.0.0.1:9118/trailer?title=Зверь&year=2026` на приставке отвечает HTTP 200, а в логе boot-хука есть строки `rc=0` для JacRed и для сервиса трейлеров

#### Scenario: Повторный запуск
- **WHEN** скрипт запуска вызван, когда сервис уже работает
- **THEN** второй экземпляр не поднимается, скрипт печатает `already running` и выходит с кодом 0
