## Context

Память рядов «Сейчас смотрят» — ключ `kp_now_watching_seen`: `{ <url ряда>: { <id KP-карточки>:
{ f, s, l } } }` (design.md изменения `now-watching-new-first`, решение 1). Метку «новинка» (`f > 0`)
снимает `markOpened(id)` из обёртки `KP.full` по id `KP_<n>`. Карточки источников `tmdb` и `cub`
открываются их `full` с `{ method, id }` — TMDB-тайтлом. Причина и воспроизведение — proposal.md, **Why**.

## Standard approach

Платформа, на которой стоят решения, уже наблюдалась на приставке, повторно не замерялась:

- Открытие карточки `tmdb`/`cub` (история, ряды ядра) вызывает `full` своего источника с `{ method, id }`,
  `id` — TMDB id, `method` — `movie`/`tv`; на возврате и на Главной вызовов нет — наблюдения 1, 5, 6 в
  `openspec/changes/archive/2026-11-21-card-trailers-any-source/design.md`. На этом уже работает обёртка
  `source.full` для трейлеров (spec `kp-card-trailers`).
- id карточки ряда `KP` и `KP.full` один — `KP_<n>` (`kp_source.js:206`, `:639-643`; «Standard
  approach» в `openspec/changes/archive/2026-11-21-now-watching-new-first/design.md`).

Как сопоставляет карточки разных источников ядро Lampa: тайм-коды просмотра ищутся по
`Utils.hash(original_title)` — `src/interaction/timeline.js:248` в
`https://github.com/yumata/lampa-source` (ветка `main`, прочитано 2026-11-21 через `gh api`). Это
сопоставление по оригинальному названию без года; почему оно здесь не подходит — решение 1.

Готового плагина, снимающего метку новинки при открытии из другого источника, нет: метка — своя
функция этого плагина (spec `now-watching-new-releases`), чужой код её не знает.

## Goals / Non-Goals

**Goals:** открытие карточки `tmdb`/`cub` того же тайтла снимает метку новой KP-карточки ряда; сбой
сопоставления виден в консоли.

**Non-Goals:** другие источники, кроме `tmdb`, `cub`, `KP` (на приставке других нет — наблюдение 3 там
же); снятие метки у карточек, найденных не для новых (старые и так не подняты); ожидание поиска при
сборке Главной.

## Decisions

### 1. Ключ сопоставления — TMDB-тайтл из `resolveTitle`

У новой карточки ряда в записи памяти появляется поле `t` — `titleKey(title)`, строка `'<method>/<id>'` её TMDB-тайтла, например
`'movie/603'`. Тайтл даёт `resolveTitle` — тот же поиск, что уже служит новизне сериалов, трейлерам и
KP-истории в рекомендациях: `find` по `imdb_id`, без него — `search` по названию и году со сверкой
названия. Метод входит в ключ: id фильма и сериала в TMDB из разных пространств (сценарий «Другой тип
с тем же id»).

Альтернативы:

- **`imdb_id`.** Без запросов, но у новинок Кинопоиска его часто нет (фикстуры `BEAST`, `FOREST`
  в тестах — реальные новинки с пустым `imdb_id`), а именно новинки здесь и важны.
- **Хэш оригинального названия, как тайм-коды ядра.** Без запросов, но у KP и TMDB оригинальные
  названия расходятся (транслитерация, локализация), а без года ремейки совпадают. `resolveTitle` уже
  сверяет название с годом и опирается на `imdb_id`, где он есть.
- **Тайтлы всех карточек ряда.** Сотни `find`/`search` на первой сборке ради карточек, у которых
  снимать нечего.

### 2. Поиск — после сборки, только для новых, не держит Главную

`orderByNovelty` уже решает, какие карточки сейчас новые (`f > 0` и моложе `NEW_DAYS`); он
возвращает и их список (`fresh`, карточки ряда). `filterRows` после `save()` зовёт `resolveTitle` для
карточек `fresh` без `t` в памяти. Каждый ответ пишется сам: `editSeen(fn)` — прочитать память
`readSeen`, выполнить `fn`, записать ключ, если `fn` что-то изменила; `fn` ставит `t` записи карточки,
если та ещё есть в своём ряду. JS однопоточен, поэтому чтение-запись в одном колбэке не теряет чужих
правок; `save()` следующей сборки может затереть `t`, записанный за её 5 с ожидания (Risks). Ключ строит один помощник `titleKey(title)` — и здесь, и при открытии (решение 3).

Главная не ждёт: окно 5 с (`ROWS_TIMEOUT_MS`) остаётся только для новизны и сезонов. Новых карточек
за сборку единицы, ответы TMDB кэшируются на 7 дней. Тайтл не найден — предупреждение с названием уже
пишет `resolveTitle` (`no title match` у поиска); у предупреждения сбоя `find` названия нет, туда
добавляется `cardName(movie)` (§IV). Отдельного предупреждения нет. Запись без `t` ищется снова на
следующей сборке (из кэша, пока он жив).

`orderByNovelty` копирует запись памяти целиком, нормализуя только `s` (сейчас копирует поля `f, s, l`
поимённо и потеряло бы `t`). Форма памяти для `readSeen` не меняется: запись — объект.

Альтернативы:

- **Искать в той же сборке под `pending()`.** Задержала бы Главную на поиск тайтлов, а новые
  карточки известны только после `orderByNovelty` — нужен второй круг ожидания.
- **Брать тайтл, который сборка уже нашла `lastEpisode` для сериалов.** Убирает повтор `resolveTitle`
  у части сериалов, но даёт второй путь записи `t` (через `collectPages` и `orderByNovelty`) рядом с
  проходом после сборки, который всё равно нужен фильмам. Повтор обслуживает кэш без сети.

### 3. Снятие метки — одна функция, два места вызова

`readSeen`, `editSeen` и `markOpened` переезжают из `patch()` в раздел «Общее» (используют только
`Lampa.Storage` и `SEEN_KEY`). `markOpened(key)` через `editSeen` снимает `f` у записей, где
`id === key || entry.t === key`: id карточки ряда — `KP_<n>`, `t` — `movie/603`, совпасть они не могут.

- обёртка `KP.full` — `markOpened(params.card.id)` (как сейчас);
- обёртка `full` источников `tmdb`/`cub` в `patchSourceCards` — `markOpened(titleKey(title))`, где
  `title` — уже существующий там `{ method: params.method, id: params.id }`.

Обёртка `source.full` выбрана вместо события `full` (`Listener`): что `full` источника зовётся ровно
при открытии карточки, наблюдалось (наблюдение 6); содержимое события `start`/`complite` в сборке
Lampa на приставке не замерялось. Если `patchSourceCards` не ставит обёртку (нет `tmdb.full`,
`cub.full`, `tmdb.videos` или `tmdb.get`), её `console.error` дополняется словами «открытие не
снимает метку новинки».

## Risks / Trade-offs

- Карточку TMDB открыли раньше, чем пришёл её тайтл (секунды после сборки) → метка не снята до
  открытия заново. Принято: окно — время одного ответа TMDB.
- `resolveTitle` нашёл не тот тайтл → открытие чужой карточки снимет метку. Та же точность, что у
  трейлеров и новизны сериалов; последствие — карточка раньше времени встаёт на место.
- `save()` сборки пишет память, прочитанную до её ожидания (≤ 5 с): `t` или снятая метка, записанные
  в это окно, теряются. `t` восстанавливается следующей сборкой из кэша; снятой метки это касается и
  сейчас для `KP.full`.
- Лишние запросы: один `find`/`search` на новую карточку, повтор только при ненайденном тайтле.

## Migration Plan

Поле `t` добавочное: старая версия плагина при сборке копирует только `f, s, l` и молча его
отбрасывает, новая версия дописывает его заново. Раскатка и откат — пин `kp-reactions-fix.js` на
sha со снапшотом по `docs/snapshots-convention.md`, как у прошлых изменений плагина.
