# Настройка 4K/HDR: TorrServe + Lampa + Ugoos AM6 + Samsung TV

Статус на 2026-08-19. См. [device-ugoos-am6.md](device-ugoos-am6.md) для доступа к устройству.

## Что уже проверено и исправлено на реальном устройстве

- HDMI output: **2160p60hz** (4K@60) — было в порядке изначально, TV подтверждает
  этот режим как согласованный.
- Глубина цвета HDMI была зафиксирована на **4:2:0, 8-bit**, хотя и приставка,
  и TV поддерживают 10-bit — это мешало честному HDR10 (риск бандинга, TV мог
  некорректно переключаться в HDR-режим). **Исправлено**: переключено на
  **4:2:0, 10-bit** через штатное меню приставки (Настройки → Настройки устройства →
  Экран → Разрешение экрана → Настройки цветового режима → «Цветовой режим для
  4k50-60Hz» → YCbCr420 10bit), подтверждено и сохранено (переживает перезагрузку).
- **Dolby Vision** телевизор Samsung **не поддерживает** (подтверждено запросом
  EDID напрямую с приставки: `dv_cap` → "The Rx don't support DolbyVision").
  Все инструкции/гайды про настройку Dolby Vision (FEL/MEL, CoreELEC и т.п.) для
  этого TV нерелевантны — фокус только на HDR10/HDR10+.
- TV заявляет поддержку **HDR10 (ST2084) и HDR10+** — эти форматы будут работать
  корректно после фикса глубины цвета.
- Аудио по EDID TV (`aud_cap`): PCM, AC-3, **Dolby Digital+/Atmos**, **MAT**
  (формат для TrueHD/Atmos). **DTS/DTS-HD в списке нет** — DTS-дорожки, скорее
  всего, будут даунмикшены в PCM, а не пройдут bitstream'ом. Если критично слышать
  оригинальную DTS-дорожку — искать релизы с Dolby-аудио (AC3/EAC3/TrueHD/Atmos)
  вместо DTS, либо не рассчитывать на честный DTS passthrough в этой связке.

## Ещё не проверено на устройстве (осталось на будущее)

- Фактический режим аудио-вывода в самой приставке (Auto/PCM/Passthrough) —
  найдено, что платформенный флаг `ro.vendor.platform.disable.audiorawout=false`
  не блокирует raw-вывод, но конкретный переключатель формата в UI ещё не найден
  и не проверен.
- Настройки TorrServe (буфер/кэш) — пока только общие рекомендации из поиска
  в интернете, не сверялись с реальным конфигом TorrServe на этой приставке.
- Настройка VLC как внешнего плеера в Lampa — не проверялась вживую.

## Общие best-practice рекомендации (из открытых источников, не проверено на месте)

**TorrServe** (Lampa обычно указывает на `http://localhost:8090`):
- RAM-кэш (`cache_size_mb`): ~800–1024 МБ для тяжёлых 4K/BDremux-файлов.
- Preload buffer (`preload_mb`): ~50–100 МБ — достаточно для быстрого старта без
  «проедания» кэша, пока скорость скачивания не разгонится. Слишком большой
  preload при медленных первых пирах — частая причина подтормаживания на
  больших remux (20–80 ГБ).
- Дисковый кэш обязательно включить с запасом места.
- Настройки вторичны по сравнению с выбором раздачи: мало сидов — будет
  тормозить при любом буфере.

**Плеер в Lampa:**
- Для 4K remux с HDR лучше внешний плеер (VLC), чем встроенный веб-плеер Lampa —
  он стабильнее держит высокий битрейт.
