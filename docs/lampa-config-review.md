# Аудит конфигурации Lampa (top.rootu.lampa) на Ugoos AM6

Статус на 2026-08-19. Конфигурация снята с устройства через ADB
(`/data/data/top.rootu.lampa/shared_prefs/settings.xml` и WebView LocalStorage
`app_webview/Local Storage/leveldb`, распаршен вручную т.к. значения сжаты Snappy).

Документ описывает **текущее состояние**. История правок — в
[../snapshots/](../snapshots/), сюда не дублируется.

## Как снималось (для повторного использования агентом)

```
MSYS_NO_PATHCONV=1 adb -s 192.168.10.5:5555 shell "cat /data/data/top.rootu.lampa/shared_prefs/settings.xml"
MSYS_NO_PATHCONV=1 adb -s 192.168.10.5:5555 pull "/data/data/top.rootu.lampa/app_webview/Local Storage/leveldb" ./lampa_ls
```

LevelDB-файлы (`*.ldb`) сжаты Snappy (raw block format, не framed) — штатные `strings`/`grep`
по бинарнику ничего не находят. Разобраны питоновским скриптом на `cramjam.snappy.decompress_raw`
(парсер SSTable-блоков + varint-декодирование ключей/значений). Учитывать, что один и тот же
ключ может встречаться в нескольких `.ldb`-файлах с разными версиями — актуальное значение
то, что находится в файле с наибольшим номером (более поздняя SST).

## Текущее состояние — что уже настроено

**Аккаунт / синхронизация:** привязан CUB-аккаунт (`account_use=true`),
синхронизация включена. **TMDB** ходит через прокси `beta.l-vid.online` с токеном привязки
к аккаунту (в файле `settings.xml` на устройстве, не привожу здесь — секрет). В настройках
TorrServer тоже стоит адрес этого провайдера, но фактически торренты играет **локальный
TorrServe на приставке** — см. отдельный раздел ниже.

**Плеер:** `ext_player=vlc`, `ext_player_inited=1` — **внешний VLC уже подключён и
инициализирован**. Это совпадает с best-practice рекомендацией (VLC стабильнее держит
тяжёлые 4K/HDR потоки, чем встроенный веб-плеер). ✅ Менять не нужно.

**Качество по умолчанию:** `video_quality_default=2160` (4K). ✅ Уже максимальное.

**Источник каталога:** `source=KP` — каталог Кинопоиска от плагина `kp_source`, чтобы
на Главной были русские фильмы вперемежку со штатными рядами (штатный `tmdb` даёт только

[../snapshots/2026-08-19_install-kp-source/NOTES.md](../snapshots/2026-08-19_install-kp-source/NOTES.md).

**Фильтр раздач:** `torrents_filter.quality = ["4k","1080p"]`, `torrents_sort=popular`
(сортировка по популярности — разумный дефолт, чтобы не попадать на раздачи без сидов). ✅

**Парсер торрентов:** `parser_use=true`, `parser_torrent_type=jackett`,
`jackett_url=Jac.red` — **Jackett-парсер уже включён и указывает на публичный
агрегатор Jac.red**. Это именно то, что рекомендуют актуальные гайды по Lampa
(поиск раздач через Jackett-совместимый индексатор). ✅ Менять не нужно.

**Чёрный список плагинов:** `plugins_blacklist` содержит ~19 известных рекламных/вредных
доменов (`ads.js`, `lampatv.fun`, `uspeh.sbs`, и т.п.) — похоже на автоматически
поддерживаемый CUB-аккаунтом список. ✅ Не трогать. Сверх него движок **захардкоженно**
добавляет в blacklist ещё `lipp.xyz`, `llpp.xyz`, `scabrum.github.io`, `bylampa.github.io`,
`tinyurl.com`, `t.me/`, `4pda.`, `teletype.in` (видно в `Lampa.Plugins.task`) — плагины
с этих доменов не загрузятся в принципе.

**⚠️ Список плагинов правится не только вами.** В LocalStorage есть ключ
`onlymodels_plugins_backup_before_gpbx_w_v1` — резервная копия списка плагинов, сделанная
чужим тулингом. Если в списке появится плагин, которого вы не ставили, это не сбой,
а установка со стороны провайдера аккаунта.

Механика (по коду `Lampa.Plugins.task()`): грузится **объединение двух списков** —
серверного из `Account.Api.plugins()` (кэшируется в ключ `account_plugins`) и локального
`plugins`. Облако локальный список только дополняет и **перетереть не может** — значит
свои плагины переживают синхронизацию. Но и обратное верно: удалённый из `plugins` плагин
вернётся, если он есть в серверном списке. Сейчас `account_plugins` пуст.

## TorrServer: в конфиге облачный адрес, играет локальный TorrServe

В конфиге веб-Lampa стоит облачный адрес: `internal_torrclient=false`,
`torrserver_url=https://beta.l-vid.online/ts`, `torrserver_auth=true` (логин/пароль
от аккаунта), и `Lampa.Torserver.url()` в рантайме возвращает именно его.

**Но воспроизведение идёт не через него.** Прослежено на живом запуске фильма
(event-лог Android + сокеты + API самого TorrServe):

```
am_create_activity  ru.yourok.torrserve/.ui.activities.play.PlayActivity
                    action.VIEW  magnet:?xt=urn:btih:6DB019B7…
am_create_activity  org.videolan.vlc/.gui.video.VideoPlayerActivity
                    action.VIEW  video/*  http://localhost:8090/…
```

То есть цепочка такая: **Lampa-обёртка (`top.rootu.lampa`) отдаёт magnet-ссылку
приложению TorrServe через Android Intent** → локальный TorrServe (`ru.yourok.torrserve`,
версия `MatriX.142`, слушает `0.0.0.0:8090`) добавляет торрент и качает его сам →
запускает VLC с `http://localhost:8090/…`. Подтверждения: в списке торрентов локального
сервера появляется запись `[LAMPA] <название>` со статусом `Torrent working`, а в
`/proc/net/tcp` висит ESTABLISHED-соединение `127.0.0.1:8090` от uid VLC.

Отсюда: **торренты качает приставка**, скорость и буферизация зависят от домашнего
канала и от настроек локального TorrServe, а не от чужого сервера. Уведомление TorrServe
со скоростью и пирами, которое видно при старте фильма, — это оно и есть.

Веб-настройка `torrserver_url` на этом пути не участвует. Она приходит из бандла
провайдера (`on.js` → плагин `ts`) и относится к другому сценарию — когда торрент
играется средствами самой веб-Lampa, без внешнего приложения (другое устройство,
встроенный плеер). Где именно она срабатывает на этой приставке — не проверялось;
менять её не нужно.

Практический вывод: **тюнить надо локальный TorrServe** (буфер/кэш/предзагрузка
в приложении `ru.yourok.torrserve`), а не искать настройки в Lampa. **Вопрос отложен
по просьбе пользователя** — пока проблем со стримингом нет, не трогаем.

**Два критерия, по которым оценивается польза плагина:**

1.  **4K/HDR с торрентов бесплатно.** Онлайн-кинотеатры (Filmix, Rezka, Kodik и прочие

### Итог по плагинам

**Русское кино приходит с двух сторон, и они не дублируют друг друга:** `kp_source` даёт
три ряда на самой Главной (топ русского по числу оценок за всё время), `p.js` — пункты
левого меню с новинками 2023–2026 и подборками стримингов. Подробнее о разграничении —
«Какой русский контент попадает на Главную, а какой нет» ниже.

Единственная зависимость, которую надо помнить: подборка «Русские фильмы» ходит в источник
`cub`, то есть требует живого аккаунта — а значит `on.js` трогать нельзя.

**Балансеры онлайн-источников (Filmix, BwaRC и подобные) под этот сценарий не нужны:**
бесплатно они отдают ≤1080p, а при открытии карточки каждый опрашивает свои бэкенды и
тормозит интерфейс. Единственный сценарий, где они полезны, — тайтл, на который вообще
нет раздачи с сидами (старое, редкое, отдельные серии). Если такой fallback понадобится,
ставить один (BwaRC), а не несколько.

## План (не применено)

1.  **(Отложено пользователем)** Привести конфиг в соответствие с реальностью:
    воспроизведение и так идёт через локальный TorrServe (см. раздел выше), а
    `torrserver_url` в веб-настройках указывает на облако провайдера. Пока проблем
    со стримингом нет — не трогаем. Если тюнить буфер/кэш — тюнить приложение
    `ru.yourok.torrserve`, в Lampa этих настроек нет.
2.  **Формат аудио (DTS)**: как и раньше зафиксировано в 4k-hdr-setup.md — TV не берёт DTS
    bitstream. Стоит проверить, не выполняет ли TorrServer транскодирование аудио на лету
    (плагин `transcoding.js` в бандле подсказывает, что это возможно) — это может решить
    проблему с DTS-дорожками автоматически.
3.  Всё остальное (VLC, качество 2160p, Jackett-парсер, фильтр по 4K/1080p, чёрный список
    рекламных плагинов, `rating.js`, `p.js`, `on.js`, источник `KP`) уже настроено
    правильно и совпадает с best-practice — менять не надо.

## Как добавить русские фильмы на вкладку «Главная»

### Почему их там нет

Проверено по коду живого движка (через `tools/cdp.py`, `Api.sources.tmdb.main.toString()`):
главная собирается из захардкоженных **глобальных** эндпоинтов TMDB —
`movie/now_playing`, `trending/movie/day`, `trending/movie/week`, `movie/upcoming`,
`movie/popular`, `trending/tv/week`, `movie/top_rated`, `tv/top_rated`. Ни один из них
не принимает страну или язык оригинала. `tmdb_lang=ru` меняет только язык названий
и описаний, но не состав выдачи. У источника `cub` то же самое (`?sort=now_playing`,
`?sort=latest`, `top/fire/movie`, `top/hundred/movie`).

Русские подборки от `p.js` — это **пункты меню**: каждая делает `Activity.push` на отдельный
экран `category_full`. По устройству они не могут попасть на главную. Поэтому «перенести
вкладку на главную» настройкой нельзя.

Отсюда ровно два способа получить русское на главной: **добавить свои ряды** через штатную
точку расширения, либо **сменить источник каталога** на тот, у которого главная изначально
русская. Оба закрываются готовыми плагинами — писать свой не нужно.

### Механизм, на котором это работает: `Lampa.ContentRows`

В движке есть штатная точка расширения (контракт снят с рантайма, не из статей):

*   `add({name, title, screen, index, call})` — регистрирует ряд; обязателен `call`.
*   `call(screen, params, calls)` — вызывается **и** из `Api.sources.tmdb.main()`, **и** из
    `Api.sources.cub.main()` перед отдачей главной; вставляет ряд через
    `Arrays.insert(calls, row.index || 0, result)`.
*   `init()` регистрирует раздел настроек `content_rows` с названием **«Каналы»**. У каждого
    ряда свой переключатель — ключ `content_rows_<name>`, по умолчанию включён. То есть
    добавленные ряды отключаются штатно в **Настройки → Каналы**.

Знать это полезно для диагностики: если ряд от плагина «пропал», первым делом смотреть
именно **Настройки → Каналы**.

⚠️ **`ContentRows` работает только на источниках `tmdb` и `cub`** — вызов сидит внутри их
`main()`. У сторонних источников (в том числе установленного `KP`) своя `main()` без этого
вызова, поэтому ряды от плагинов на их главной не появляются вообще.

Оба варианта прогнаны на устройстве (загрузка через `tools/cdp.py`, без записи в конфиг).
Протоколы прогонов со скриншотами — [../snapshots/2026-08-19_try-surs/NOTES.md](../snapshots/2026-08-19_try-surs/NOTES.md)
и [../snapshots/2026-08-19_try-kp-source/NOTES.md](../snapshots/2026-08-19_try-kp-source/NOTES.md).

### Вариант 1 — SURS: ряды на главную, источник остаётся TMDB

`https://aviamovie.github.io/surs.js`

Что это по коду: сам `surs.js` — 6-килобайтный загрузчик, он подтягивает четыре модуля
`aviamovie.github.io/v3/`: `surs.js`, `surs_nav_buttons.js`, `surs_strmngs_row.js`,
`surs_genres_row.js`. Ряды регистрируются через `Lampa.ContentRows.add` —
`{index: 3, name: 'streaming_global'}` и `{index: 7, name: 'streaming_russian'}`.

**Что оказалось на устройстве:** ряды «Российские стриминги», «Глобальные стриминги»,
«Жанр» — это ряды **кнопок-ярлыков** (логотипы сервисов, названия жанров), а не постеров
фильмов. Русского контента на главной они не дают, только ссылки на подборки — то же,
что уже делает `p.js` в левом меню. Плюс косметический баг: в карточках виден
неподставленный шаблон `{release_year}`.

Русский контент SURS даёт по-другому — четырьмя **собственными источниками каталога**
(`SURS`, `SURS NEW`, `SURS KIDS`, `SURS RUS`). При `source = SURS RUS` главная целиком
русская («Новинки на Premier / Start / КION / Первый канал / СТС», «Новинки Российские
сериалы (драмы / детективы / детское / реалити-шоу)»). Но это **полная замена**:
западного контента не остаётся вообще, уклон в свежие сериалы российских стримингов,
штатные ряды TMDB исчезают.

Побочные эффекты: при первом запуске безусловно пишет `interface_size: normal → small`
и создаёт ключ `surs_settings`; добавляет свой раздел настроек; ~250 КБ на старте.

Проверка кода: во всех четырёх модулях **ноль внешних хостов** (единственный найденный URL —
`w3.org` в атрибутах SVG) и ноль аналитики — все запросы идут через родной `Lampa.Api`.
В комментариях автор просит донат, платного гейта в коде нет.

### Вариант 2 — kp_source: Кинопоиск как источник каталога ✅ рекомендуется

`https://nb557.github.io/plugins/kp_source.js`

Автор — тот же nb557, чей `rating.js` уже стоит и уже проверен.

Что делает: регистрирует источник `KP` (`Lampa.Api.sources['KP']` +
`Lampa.Params.select('source', …)`), после чего он появляется в
**Настройки → Основной источник**. Главная у источника KP собирается из коллекций
Кинопоиска: «Сейчас смотрят фильмы» / «Сейчас смотрят сериалы»
(`films/collections?type=TOP_POPULAR_MOVIES` / `POPULAR_SERIES`), «Топ фильмы» / «Топ сериалы»
(Top-250), «Популярные фильмы/сериалы/мини-сериалы/телешоу» — и, если API отдаёт id страны
«Россия», в позиции 5/7/9 вставляются **«Популярные российские фильмы»**,
**«…российские сериалы»**, **«…российские мини-сериалы»**
(`films?order=NUM_VOTE&countries=<id>&type=…`).

Проверка кода: два внешних хоста — `kinopoiskapiunofficial.tech` (тот же неофициальный API
Кинопоиска, что использует `rating.js`) и CORS-прокси `cors.kp556.workers.dev`, который
включается только при 429/451 от основного. Ключи API зашиты в плагин (обфусцированы,
свой ключ регистрировать не нужно). Аналитики, сбора device-id и отправки чего-либо своего
на сторону нет. Есть `isDebug()` — на четырёх origin автора (`prisma.ws`, `lampishe.cc`,
`lampa.walsy.synology.me`, `bylampa.online`) плагин не устанавливается; `lampa.mx` в этот
список не входит, значит установится нормально.

**Что оказалось на устройстве:** главная получается **смешанная** — русские ряды
вперемежку со штатными, а не вместо них: Сейчас смотрят фильмы / сериалы, Топ фильмы /
сериалы, Популярные фильмы, **Популярные российские фильмы**, Популярные сериалы,
**Популярные российские сериалы**, Популярные мини-сериалы, **Популярные российские
мини-сериалы**, Популярные телешоу. Это ровно то, что было нужно.

Основной сценарий (4K/HDR с торрентов) не ломается — проверено:

*   карточка из русского ряда открывается, торрент-поиск через Jac.red отдаёт раздачи,
    фильтр «Качество: 4k, язык: Русский» сохраняется;
*   западный фильм ищется по русскому названию (`Интерстеллар 2014`) и всё равно находит
    4K HDR BDRip 2160p с сотнями сидов — отсутствие оригинального названия в карточке КП
    поиску не мешает;
*   в LocalStorage плагин **не пишет ничего** (142 ключа до и после), своего раздела
    настроек не добавляет.

Косметика: на карточке рейтинг КП показывается дважды. Это **не** `rating.js` — третий
бейдж это элемент `.rate--tmdb`, куда движок кладёт `vote_average` активного источника
и подписывает его именем источника (`KP`), а `kp_source` пишет туда тот же рейтинг
Кинопоиска. Отключение `rating.js` дубль не убирает (проверено).

Цена: меняется **весь каталог**, а не только главная — поиск, фильтры и карточки идут
в Кинопоиск. Подборки `p.js` при этом продолжат работать: они явно указывают source
`cub`/`tmdb` в своих `Activity.push`. Риск — неофициальный API с общими ключами, то есть
возможны 429 в часы пик (на этот случай в плагине и сделан прокси-фолбэк).

### Что не подойдёт

`https://bylampa.github.io/rus_movie.js` («Русские новинки») — по двум причинам.
Во-первых, домен `bylampa.github.io` **захардкожен в чёрный список самого движка**
(`Lampa.Plugins.task()` добавляет его вместе с `lipp.xyz`, `scabrum.github.io`,
`tinyurl.com`), плагин просто не загрузится. Во-вторых, он всё равно добавляет пункт
в левое меню, а не ряд на главную — то есть делает то же, что уже делает `p.js`.

### Что выбрано и стоит сейчас

**Установлен kp_source, источник переключён на `KP`.** Он единственный делает то, что
требовалось — русские ряды *на общей* главной, — при этом ничего не пишет в настройки,
не трогает интерфейс и не ломает торрент-сценарий. SURS свою задачу решает только через
полную замену главной на исключительно русскую (`SURS RUS`), а его ряды на TMDB-главной —
просто кнопки-ярлыки.

Ставилось из CLI (см. [../tools/README.md](../tools/README.md)) двумя шагами с проверкой
после каждого:

```js
Lampa.Plugins.add({ url: 'https://nb557.github.io/plugins/kp_source.js', name: 'KP source', status: 1 });
Lampa.Storage.set('source', 'KP');   // плагин только регистрирует источник, применить надо отдельно
```

Протокол установки и проверок —
[../snapshots/2026-08-19_install-kp-source/NOTES.md](../snapshots/2026-08-19_install-kp-source/NOTES.md).

После — перезагрузить страницу и проверить: главная грузится, русские ряды на месте,
подборки `p.js` в левом меню живы, карточка фильма открывается, торрент-поиск через Jac.red
возвращает раздачи.

Прогнать плагин без установки можно инъекцией через `tools/cdp.py` — код выполнится сразу,
в конфиг ничего не запишется, состояние сбросится перезагрузкой страницы.

### Какой русский контент попадает на Главную, а какой нет

Главная у `kp_source` — это **фиксированный список из 11 запросов** к Кинопоиску,
захардкоженный в `main()`; ни настроек, ни точки расширения у него нет. Русских рядов
ровно три, и все три построены одинаково:

```
api/v2.2/films?order=NUM_VOTE&countries=<id России>&type=FILM | TV_SERIES | MINI_SERIES
```

`order=NUM_VOTE` = сортировка по **количеству оценок за всё время**, фильтра по годам нет.
Отсюда состав: «Брат», «Холоп 2», «Батя», «По щучьему велению» — вечная классика и
народные хиты, а не новинки. Свежий русский фильм попадёт в этот ряд не тогда, когда
выйдет, а когда наберёт голоса — то есть спустя месяцы или никогда.

**Подборки `p.js` на Главную не попадают и попасть не могут.** Проверено по коду:
в `p.js` **ноль** обращений к `Lampa.ContentRows` — он умеет только добавлять пункты
в левое меню, каждый делает `Activity.push` на отдельный экран `category_full`.
Настройки, которая «перенесла бы вкладку на главную», не существует.

Содержательно они и не дублируют KP-ряды:

| Пункт меню `p.js` | Что это на самом деле | Пересечение с Главной |
| --- | --- | --- |
| «Русские» | `cub`: `?cat=movie&airdate=2023-2026&without_genres=16&language=ru` — **новинки** русского кино за последние годы | ❌ нет: на Главной ранжирование по числу голосов за всё время |
| «В качестве» | `cub`: `?cat=&sort=now&uhd=true` — то, что доступно **в 4K** | ❌ нет |
| Кинопоиск, Okko, ИВИ, START, Wink, KION, Premier, Amediateka | TMDB `discover/tv?with_networks=<id>` — **сериалы** конкретной площадки | ❌ нет |

Итог: полного покрытия «все русские фильмы на Главной» не существует ни при каком
сочетании готовых плагинов. Реальные варианты:

1.  **Оставить как есть** (текущий выбор): Главная — топ русского за всё время + мировые
    ряды; новинки и 4K-подборки — в один клик из левого меню. Ничего не ломается.
2.  **Сменить источник на `SURS RUS`** — Главная станет целиком русской и именно из
    новинок стримингов, но западный контент с неё исчезнет полностью (см. вариант 1 выше).
3.  Свой плагин. Штатный путь `ContentRows` тут **не сработает**: `ContentRows.call()`
    вызывается только из `Api.sources.tmdb.main()` и `cub.main()`, а в `main()` у
    `kp_source` его нет (0 вхождений) — сторонние ряды на KP-главной не отрисуются.
    Это же объясняет, почему связка «KP + ряды SURS» бессмысленна. Но обойти это можно —
    обёрткой над `main` самого `kp_source`, см. «Как менять поведение чужого плагина» ниже.

## Best practice по настройке и кастомизации Lampa

**Где искать проверенную информацию (не догадки):**

*   **Самый точный источник — сам движок в рантайме.** Через `tools/cdp.py` можно
    вытащить исходник любой функции и любой внутренний список:
    `Lampa.ContentRows.call.toString()`, `Lampa.SettingsApi.allComponents()`,
    `Object.keys(Lampa.Api.sources)`, `Lampa.Plugins.task.toString()`. Всё, что
    в этом документе описано как «проверено по коду живого движка», получено так —
    отвечает именно та версия, что стоит на устройстве.
*   У Lampa нет официальной опубликованной документации по API плагинов — сам движок
    закрыт (обфусцированный `app.js`). Ближайший читаемый ориентир —
    [github.com/yumata/lampa-source](https://github.com/yumata/lampa-source), открытое
    зеркало фронтенда с неминифицированным кодом, включая папку `plugins/online/` —
    это реальные рабочие плагины-источники.
*   Автосгенерированная документация по этому репозиторию на DeepWiki:
    `deepwiki.com/yumata/lampa-source/12.2-plugin-api-and-integration-points` — описывает
    регистрацию UI-компонентов через `Lampa.Component.add()` и жизненный цикл плагина:
    `create()` → `start()` → `pause()`/`stop()` → `destroy()`.
*   Для проверки _любого_ незнакомого плагина, прежде чем доверять ему: скачать сам JS
    (`curl -A "Mozilla/5.0 ..." <url>`, браузерный User-Agent часто обязателен) и прочитать
    код напрямую — искать домены аналитики (`google-analytics`, `mc.yandex`, `webvisor`),
    запросы на сторонние бэкенды, сбор device-id/fingerprint. Быстрый первый прогон —
    список всех `https?://` хостов в файле: если там только API самого каталога, вопросов нет.

**Как менять настройки Lampa:**

1.  **Штатный путь из CLI — `tools/cdp.py`**: выполнить JS в контексте живой страницы
    и дёрнуть родное API — `Lampa.Storage.get/set`, `Lampa.Plugins.add/remove`,
    `Lampa.Settings`. Это ровно тот же код, который выполняется при правке через UI,
    поэтому облачная синхронизация остаётся консистентной. Детали и команды —
    [../tools/README.md](../tools/README.md).
2.  **Чего делать нельзя** — править `app_webview/Local Storage/leveldb` напрямую
    (`adb push` файла, бинарная правка). Формат бинарный, приложение держит его открытым,
    а облако всё равно может перетереть локальную правку. Единственное легальное применение
    LevelDB — **чтение** для аудита.
3.  Перед добавлением незнакомого плагина — прочитать код (см. выше), а не полагаться
    на название/описание в сторонних каталогах плагинов.
4.  Держаться `plugins_blacklist` — не отключать его.
5.  Одно изменение за раз: добавил/удалил → проверил, что просмотр и поиск не сломались →
    только потом следующее.
6.  Перед любым изменением — снапшот по конвенции [snapshots-convention.md](snapshots-convention.md).
    Список плагинов синхронизируется с облаком, поэтому откат «просто вернуть файл»
    не работает — откатывать надо тем же путём, каким менял.

**Прежде чем писать свой плагин — поискать готовый.** Экосистема Lampa большая, и типовые
задачи («русский контент на главной», «Кинопоиск как источник», «свои подборки») уже закрыты.
Свой плагин оправдан, только когда готового действительно нет: его придётся где-то хостить
(движок грузит плагины только по URL через `<script src>`) и поддерживать самому.

Если всё же нужен свой — минимальный каркас (ждём готовности приложения, иначе `Lampa.*`
ещё нет):

```js
(function () {
  'use strict';
  function startPlugin() {
    Lampa.Component.add('my_source', {
      create: function () { /* инициализация */ },
      start: function () { /* запрос к источнику, рендер результатов */ },
      pause: function () {},
      stop: function () {},
      destroy: function () {}
    });
  }
  if (window.Lampa) startPlugin();
  else Lampa.Listener.follow('app', function (e) {
    if (e.type == 'ready') startPlugin();
  });
})();
```

Дальше — по типу задачи: ряд на готовый экран — `Lampa.ContentRows.add(...)`; свой
экран/источник — `Lampa.Component.add(...)`; свои настройки —
`Lampa.SettingsApi.addComponent/addParam`; запросы к каталогу —
`Lampa.Api.sources.tmdb.get(url, params, ok, err)` (штатных источников ровно два,
`tmdb` и `cub`, плагины добавляют свои).

### Как менять поведение чужого плагина

Изоляции между плагинами нет: все они грузятся как обычные `<script>` в один и тот же
контекст страницы и складывают свои объекты в глобальный `Lampa`. Значит **любой чужой
плагин можно переопределить своим** — не форкая его.

Работает так: плагин, загруженный позже, берёт нужный метод и оборачивает его.
Проверено на устройстве — вставка своего ряда в главную источника `KP`, который
`ContentRows` не поддерживает:

```js
var KP  = Lampa.Api.sources.KP;
var org = KP.main;
KP.main = function (params, oncomplite, onerror) {
  return org.call(KP, params, function (rows) {
    rows.splice(1, 0, { title: 'Свой ряд', results: [/* карточки */] });
    oncomplite(rows);
  }, onerror);
};
```

Ряд появился на главной между штатными — то есть ограничение «на KP-главную свои ряды
не добавить» обходится, просто не штатной точкой расширения.

Что надо помнить:

*   **Порядок загрузки.** Патч должен выполниться после патчируемого плагина: движок
    грузит список `plugins` сверху вниз (серверные записи идут перед локальными),
    поэтому патч ставить ниже цели. Надёжнее — не полагаться на порядок, а дождаться
    появления объекта (`Lampa.Listener.follow('app', …)` + проверка на существование).
*   **Обёртка, а не копипаста.** Сохранять оригинал и вызывать его — тогда обновление
    чужого плагина не ломает патч, пока не меняется сигнатура.
*   **Хостинг.** Движок грузит плагины только по URL (`<script src>`), поэтому свой
    патч нужно где-то держать — GitHub Pages, raw-gist, любой статический HTTPS.
    Это и есть основная цена своего кода: хостить и поддерживать самому.
*   **Альтернатива — форк.** Скачать `kp_source.js`, поправить, положить рядом и
    поставить свою копию вместо оригинала. Проще в написании, но обновления автора
    придётся переносить руками, поэтому обёртка обычно дешевле в поддержке.
*   Патч без установки удобно отлаживать инъекцией через `tools/cdp.py` — код выполняется
    сразу, в конфиг ничего не пишется, перезагрузка страницы всё сбрасывает.
