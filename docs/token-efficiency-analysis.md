# Расход токенов в агентных сессиях: замер и план

Замер сделан по транскриптам реальных сессий (`~/.claude/projects/<project>/*.jsonl`),
поле `usage` API-ответов, дедупликация по `message.id` — без дедупликации цифры
завышены примерно вдвое, потому что `usage` дублируется по каждому content-блоку сообщения.

## Baseline

Основная сессия: 6 часов непрерывной работы, 41 реплика пользователя.

| Метрика | Значение |
|---|---|
| Обращений к модели | 575 |
| Входные токены (cache_read + cache_create) | **59.3M** (58.0 + 1.23) |
| Выходные токены | 358.6K |
| Средний контекст на обращение | 103K (min 40K, max 169K) |
| Автокомпактов | 5 |
| Отношение input : output | **165 : 1** |
| На одну реплику пользователя | ~1.45M токенов, 14 обращений |

Две реплики стоили 13.0M и 11.6M токенов — 114 и 130 шагов каждая.

### Куда ушли 59.3M

| Доля | Что |
|---|---|
| ~23M (39%) | Базовый контекст (~40K: системный промпт, схемы инструментов, список скиллов, CLAUDE.md), умноженный на 575 обращений |
| ~31M (53%) | Накопленная история диалога |
| ~3–5M (5–8%) | 54 скриншота: 23 МБ base64, 2675 «экспозиций» (сколько раз картинка перечитывалась последующими обращениями до компакта) |

Дисциплина по объёму вывода была нормальной: средний `tool_result` от Bash — 717 байт,
доля обращений, закончившихся ошибкой — 4%. Проблема не в размере отдельных выводов.

**Драйвер стоимости — количество обращений к модели.** Каждое тащит полный контекст.
Урезание базового контекста на 20% экономит 8% сессии; сокращение числа обращений
вдвое экономит ~50%.

## Антипаттерны

### A1. Пошаговое управление устройством — 239 обращений (42% всех)

| Категория | Обращений |
|---|---|
| `cdp.py` с одним JS-выражением | 89 |
| ADB-навигация (119 keyevent, ~1.8 нажатия за обращение) | 65 |
| Прочий ADB | 64 |
| `screencap` | 21 |

Навигация по UI шла вслепую: нажал → снял экран → посмотрел → нажал. Каждое нажатие
пульта — отдельный запрос с контекстом ~100K.

### A2. Скриншот вместо текстового состояния

54 изображения — 98.6% всего объёма `tool_result` (22.4 МБ из 23.4 МБ). Картинка живёт
в контексте до следующего компакта, поэтому её цена — не 1.5K токенов, а 1.5K × число
последующих обращений. Именно скриншоты разгоняли контекст до 169K и провоцировали компакты.

### A3. Веб-ресёрч в основном контексте

19 WebSearch + 11 WebFetch, ни одного субагента. 62 КБ выдачи осели в контексте до конца
сессии, хотя полезного вывода в них было на несколько строк.

### A4. Документ пишется раньше согласованных критериев

Один документ: 36 правок + 10 чтений (62.6 КБ). Переделывался дважды целиком, потому что
ось оценки выбрал агент, а не пользователь.

### A5. Компакт как способ управления контекстом

5 автокомпактов. Каждый сбрасывает кэш (отсюда 1.23M дорогих cache_creation вместо дешёвого
cache_read) и заставляет переоткрывать уже принятые решения.

### A6. Шум окружения

Подключённые, но ни разу не использованные MCP-коннекторы — 85 имён инструментов в каждом
из 575 обращений. Плюс скрипты падали на кодировке консоли Windows (`UnicodeEncodeError`),
что стоило лишних циклов.

## План

Задачи заведены отдельными Issues:

1. Batch-режим для `cdp.py` — пачка выражений за одно обращение (89 → ~20).
2. `tools/ui.py` — сценарная навигация вместо пошаговых keyevent (65 → ~10).
3. Текстовый снимок экрана вместо скриншота (`uiautomator dump` / DOM через CDP).
4. Правило: веб-ресёрч от 3 источников — в субагента.
5. Критерии оценки зафиксированы до написания документа; сначала скелет на подтверждение.
6. Гигиена окружения: отключить неиспользуемые MCP-коннекторы, `PYTHONIOENCODING=utf-8`.
7. `tools/session_stats.py` — замер до/после, чтобы эффект был измерим, а не декларирован.

## Как мерить

Метрика приёмки — не «стало меньше токенов», а два числа на сопоставимой задаче:
**обращений к модели на одну реплику пользователя** и **средний контекст на обращение**.
Baseline: 14 и 103K.
